Appendix F — SLURM Command Reference

This appendix is a compact reference for SLURM (Simple Linux Utility for Resource Management) (Yoo et al., 2003) commands and directives on clusters like Talapas. The concepts behind them (fair-share scheduling, right-sizing, pipeline design) are explained in Chapter 20.

F.4 Job Information

Useful sacct Format Fields

Reading seff and Right-Sizing

Run seff JOBID after every job. The loop: first run with a modest over-estimate; then set the next run from what was actually used.

Defaults on Talapas if you do not specify: about 3.7 GB memory per core, 1 core, and the partition’s maximum time (24 h on compute). There is no default partition or account; both are required.

Why Is My Job Pending?

Shown in the NODELIST(REASON) column of squeue -u $USER.

F.6 SBATCH Directives

Essential Directives

#!/bin/bash
#SBATCH --job-name=my_job       # Job name (displayed in queue)
#SBATCH --partition=compute     # Partition to use (required)
#SBATCH --account=PIRG          # Account to charge (required)
#SBATCH --time=04:00:00         # Time limit (HH:MM:SS or D-HH:MM:SS)
#SBATCH --nodes=1               # Number of nodes
#SBATCH --ntasks=1              # Number of tasks (MPI ranks)
#SBATCH --cpus-per-task=4       # CPUs per task (threads)
#SBATCH --mem=16G               # Memory per node

set -euo pipefail               # stop on error / unset var / failed pipe stage
module purge                    # modules must be loaded INSIDE the script
module load R/4.3.3

Output Directives

#SBATCH --output=output_%j.log  # Standard output (%j = job ID)
#SBATCH --error=error_%j.log    # Standard error
#SBATCH --output=%x_%j.out      # %x = job name
#SBATCH --mail-user=email@uoregon.edu  # Email address
#SBATCH --mail-type=BEGIN,END,FAIL     # When to email

Resource Directives

#SBATCH --mem-per-cpu=4G        # Memory per CPU
#SBATCH --gres=gpu:1            # Request 1 GPU
#SBATCH --gres=gpu:v100:2       # Request 2 V100 GPUs
#SBATCH --constraint=intel      # Node constraint
#SBATCH --exclusive             # Exclusive node access
#SBATCH --array=1-100           # Job array
#SBATCH --array=1-100%10        # Array with max 10 running

Dependency Directives

#SBATCH --dependency=afterok:JOBID      # Run after job succeeds
#SBATCH --dependency=afterany:JOBID     # Run after job completes
#SBATCH --dependency=afternotok:JOBID   # Run after job fails
#SBATCH --dependency=singleton          # Only one job with this name

F.9 Job Arrays

Template: One Script, Many Samples

#!/bin/bash
#SBATCH --job-name=align
#SBATCH --partition=compute
#SBATCH --account=myPIRG
#SBATCH --time=02:00:00
#SBATCH --cpus-per-task=8
#SBATCH --mem=16G
#SBATCH --array=1-24%8               # 24 tasks, at most 8 running at once
#SBATCH --output=logs/%x_%A_%a.out   # %A = array job ID, %a = task ID
#SBATCH --error=logs/%x_%A_%a.err

set -euo pipefail
module purge
module load bwa/0.7.17 samtools/1.17

SAMPLE=$(sed -n "${SLURM_ARRAY_TASK_ID}p" samples.txt)   # line N = task N
OUT="results/${SAMPLE}.bam"
[[ -s "$OUT" ]] && { echo "$SAMPLE done, skipping"; exit 0; }   # resumable

bwa mem -t "$SLURM_CPUS_PER_TASK" ref.fa "raw/${SAMPLE}_R1.fastq.gz" "raw/${SAMPLE}_R2.fastq.gz" \
    | samtools sort -@ "$SLURM_CPUS_PER_TASK" -o "$OUT.tmp"
mv "$OUT.tmp" "$OUT"          # rename only after success: no truncated outputs
echo "Wrote $OUT"

Run mkdir -p logs results before submitting. The logs/ directory must exist or the job fails silently.

Array Index Variants

#SBATCH --array=0-100:10        # 0, 10, 20, ..., 100
#SBATCH --array=1-1000%50       # Max 50 running at once
#SBATCH --array=3,7,12          # Rerun only specific tasks

To size the array from a file at submit time: sbatch --array=1-$(wc -l < samples.txt) align.sh. To run a step only after every task succeeds: sbatch --dependency=afterok:ARRAY_JOB_ID next_step.sh.

F.11 Example Job Scripts

Basic R Script

#!/bin/bash
#SBATCH --job-name=r_analysis
#SBATCH --partition=compute
#SBATCH --account=myPIRG
#SBATCH --time=02:00:00
#SBATCH --nodes=1
#SBATCH --cpus-per-task=4
#SBATCH --mem=16G
#SBATCH --output=r_job_%j.log

set -euo pipefail

# Load required modules (inside the script, with a version number)
module purge
module load R/4.3.3

# Run R script
Rscript my_analysis.R

Python with Conda

#!/bin/bash
#SBATCH --job-name=python_job
#SBATCH --partition=compute
#SBATCH --account=myPIRG
#SBATCH --time=04:00:00
#SBATCH --cpus-per-task=8
#SBATCH --mem=32G
#SBATCH --output=python_%j.log

# Load conda and activate your environment
module load miniconda3/20240410
conda activate myenv

# Run Python script
python analysis.py --input data.csv --output results/

GPU Job

#!/bin/bash
#SBATCH --job-name=gpu_job
#SBATCH --partition=gpu
#SBATCH --account=myPIRG
#SBATCH --time=08:00:00
#SBATCH --nodes=1
#SBATCH --cpus-per-task=4
#SBATCH --mem=32G
#SBATCH --gres=gpu:1
#SBATCH --output=gpu_%j.log

module load cuda/12.4
module load miniconda3/20240410
conda activate ml_env

python train_model.py

MPI Job

#!/bin/bash
#SBATCH --job-name=mpi_job
#SBATCH --partition=compute
#SBATCH --account=myPIRG
#SBATCH --time=04:00:00
#SBATCH --nodes=4
#SBATCH --ntasks-per-node=16
#SBATCH --mem-per-cpu=4G
#SBATCH --output=mpi_%j.log

module load openmpi/4.1

mpirun -np 64 ./my_mpi_program
