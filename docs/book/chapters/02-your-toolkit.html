2  Your Computational Toolkit: Installing and Using Editors and IDEs

NoteLearning Objectives

After completing this chapter, you will be able to:

  • Explain what an editor and an integrated development environment (IDE) do for you, and why a small investment in learning one pays off every day
  • Install the core software for this course: a Unix shell, R, Python, Quarto, TinyTeX, VS Code, and Positron (plus RStudio if you want it)
  • Navigate the layout of VS Code and Positron, use the Command Palette and the integrated terminal, and install the extensions we rely on
  • Choose sensibly among VS Code, Positron, and RStudio for a given task
  • Keep track of which “side” of a Windows computer you are working on when using WSL
  • Distinguish Jupyter notebooks from Quarto documents, and know what a Python environment is
  • Install the compiler toolchain your operating system needs to build R and Python packages from source
  • Verify that everything is installed correctly and troubleshoot the most common installation problems

In Chapter 1 you set up the operating-system level of your computer: a Unix shell on macOS or Linux, or Windows Subsystem for Linux (WSL) with Ubuntu on Windows. This chapter fills in the rest of the toolkit. By the end you should have the languages we use (R and Python), the publishing system that turns code and prose into documents (Quarto, with a small LaTeX distribution for PDFs), and, most importantly, a comfortable place to write and run code: an editor or IDE.

We spend far more time in this chapter on the editor than on any single language. That is deliberate. Over the course of a graduate degree you will spend hundreds of hours writing scripts, documents, and analyses, and almost all of that time is spent inside an editor. Learning its layout, shortcuts, and quirks early is the single best productivity investment you can make.

NoteWhat each of these tools actually is

The install list below mixes three different kinds of software, and it helps to know which does what:

  • R, Python, and LaTeX are languages. You write code (or markup) in them and a program executes it: R and Python turn analysis code into results and figures; LaTeX turns markup into a typeset document and is what produces PDF output.
  • Quarto is a formatting and publishing system. It weaves your prose together with code chunks, runs the code through R or Python, and renders the result into an HTML page, slide deck, or PDF. It is the layer that turns a .qmd file into a finished document.
  • VS Code, Positron, and RStudio are integrated development environments (IDEs): the workbenches you sit in. Each gives you an editor, a place to run code and see output, and tools for managing projects. None of them is a language, and none is required by any other tool; they are where you do the work.

In short: R, Python, and LaTeX are languages, Quarto stitches and publishes them, and the IDEs are where you write.

2.1 Why an Editor or IDE?

Every program you write in this course, whether a Bash script, an R analysis, or a Quarto document, is a plain-text file. In principle you could write it with any tool that produces plain text, and for quick edits on a remote server, terminal editors such as nano and vim remain useful (we will meet them in Chapter 4). But plain editors do not scale to real projects. Once your work spans a dozen files across several directories, you want a tool that can show the whole project at once, that color-codes your code so structure and mistakes are visible at a glance, and that lets you run code right where you write it.

An Integrated Development Environment (IDE) bundles those capabilities into one window: a text editor with syntax highlighting and completion, a terminal for shell commands, a console for an interactive R or Python session, and tools such as a file explorer, a search across the project, and an interface to version control (Chapter 20). The three IDEs you will encounter in this course, VS Code, Positron, and RStudio, all provide these pieces; they differ mainly in emphasis, as we discuss in Section 2.7.

TipOpen the folder, not the file

All three IDEs work best when they can see your entire project. Always use File → Open Folder (or its equivalent) on the project’s top-level directory, rather than double-clicking a single file. The file explorer then shows the whole tree, project-wide search works, and the integrated terminal opens in that folder automatically, so relative paths in your scripts behave as expected.

2.2 Is Your Laptop Ready?

Before installing anything, make sure your machine can handle the software. The course requires a laptop with 16 GB of RAM (8 GB is the absolute minimum and will struggle with larger datasets later in the term), at least 20 GB of free disk space (the installs in this chapter alone take roughly 10 GB, and your data needs room too), and an up-to-date macOS, Windows 10/11, or Linux. You also need administrator rights to install software; if your laptop is managed by a lab or department, you may need to ask their IT staff for help. Chromebooks and iPads will not work for this course. If you do not have a suitable laptop, talk to the instructor early so that a solution can be found.

Some installers, R in particular, come in different versions for different processors, so it helps to know what kind of chip you have. Table 2.1 shows how to find out.

While you are there, note your RAM and free disk space. In Chapter 3 we compare these numbers to what a single node of the Talapas cluster offers; the comparison is instructive.

2.3 The Install Checklist

Here is everything you need for the course, in a sensible order. You do not need all of it on day one. The bootcamp installs a minimum viable toolkit, four things that are enough for the first several weeks, and the rest arrives in the week it is first used (Table 2.2). Several of the downloads are large, so it is worth starting them and letting them run while you read the rest of the chapter. The operating-system prerequisites (the Xcode command-line tools on macOS, and WSL with Ubuntu on Windows) are covered in Chapter 1; make sure those are finished first.

TipWhich IDE will we use?

Class demonstrations use Positron. Everything in the course also works in VS Code (the same editor underneath) and, for R, in RStudio, and you are welcome to use them; but if all of this is new to you, follow along in Positron so that what you see matches the screen at the front of the room.

A Unix shell

On macOS and Linux you already have one: open Terminal (on macOS, press Cmd-Space and type “Terminal”; on Linux, often Ctrl-Alt-T). On Windows, the shell you will use for this course is the Ubuntu installed by WSL. In practice you will usually reach the shell through the terminal panel inside Positron (Ctrl-`, the backtick key), which runs the same shell in a window next to your code; on Windows, the terminal panel’s drop-down menu offers an Ubuntu (WSL) profile. Confirm it works by typing echo $SHELL and whoami at the prompt. macOS uses zsh by default and Ubuntu uses bash; for everything in this course they behave the same.

R

Download R from CRAN at https://cran.r-project.org. Install R before Positron or RStudio, since both look for an existing R when they first start. On macOS, click “Download R for macOS” and choose the .pkg installer that matches your chip: arm64 for Apple silicon (M1 through M4) or x86_64 for Intel Macs. If you are unsure, run uname -m in Terminal (Table 2.1). Open the downloaded file and follow the prompts; R ends up in your Applications folder. On Windows, click “Download R for Windows”, then “base”, then the link for the latest version; run the .exe installer, accepting the defaults, and R appears in the Start menu. On Linux (Ubuntu/Debian), install from the package manager and confirm the version in one go:

sudo apt update
sudo apt install -y r-base r-base-dev
R --version

Other distributions have their own instructions on the CRAN site. Whichever platform you are on, a quick check that R itself works is to start it and type R.version.string; it should print something like R version 4.5.1 (2025-06-13). While you are there, install the one package collection the course leans on from Week 6 onward: install.packages("tidyverse"). It downloads a few hundred megabytes, so start it and let it run. On Windows, also install Rtools (Section 2.3.9) so that packages that need compiling can build. R is the subject of Chapter 11 and everything that follows it.

NoteWindows: install R and Python on the Windows side

If you use WSL, install R, Python, VS Code, and Positron as ordinary Windows applications, not inside Ubuntu. The IDEs run on Windows and will find the Windows copies of R and Python; Ubuntu is where you will type shell commands. Section 2.8 explains how to tell the two apart.

Python

There are three common ways to install Python 3, and for this course any of them is fine as long as you pick one and stick with it:

  • The python.org installer (simplest). Download from https://www.python.org/downloads/. On macOS, run the installer. On Windows, the first screen of the installer has a checkbox labeled “Add python.exe to PATH”: check it. If you skip it, your terminal will not be able to find Python and you will end up reinstalling.
  • uv (fastest). A single small program from https://docs.astral.sh/uv/ that installs Python versions, creates environments, and installs packages; uv python install 3.12 fetches an interpreter.
  • conda (Miniconda or Miniforge). A package manager that also installs non-Python software; it is the standard on Talapas and in bioinformatics, but heavier than the other two.

Inside Ubuntu on WSL, Python is already present, but the tools for installing packages and creating environments are not, so add them with:

sudo apt install -y python3-pip python3-venv

The trade-offs among these options, and how to use environments with each, are covered in Chapter 12.

Quarto

Quarto turns Markdown and code into HTML pages, PDFs, Word documents, and slides; it is how this book and the course slides are built. Positron and RStudio bundle the Quarto command-line tool, so if you use either of them there is nothing to install: open the IDE’s terminal and run quarto --version to confirm. If you use VS Code, or want quarto available in a shell outside any IDE, download the installer for your operating system from https://quarto.org/docs/get-started/ and run it. Quarto is covered in depth in Chapter 5.

TinyTeX

To produce PDFs, Quarto needs a LaTeX distribution, the standard system for typesetting mathematics (Chapter 18). You will not need this until Week 9, and rendering to HTML works without it, so it is fine to come back to this section later. Full distributions such as MacTeX and MiKTeX are several gigabytes; TinyTeX installs only what Quarto needs. Open a terminal and run:

quarto --version
quarto install tinytex     # takes several minutes

If you already have a full LaTeX distribution, Quarto will find and use it, and you can skip this step.

TinyTeX can also be installed from inside R, which is convenient if you have an R console open and have not yet opened a terminal. In the R console:

install.packages("tinytex")
tinytex::install_tinytex()     # takes several minutes; restart the IDE afterwards

Either route produces the same TinyTeX; do not run both. TinyTeX installs additional LaTeX packages automatically the first time a document needs them, which is why it stays small. If you would rather have a complete distribution, the standard choices are MacTeX (https://www.tug.org/mactex/, about 4 GB) on macOS, MiKTeX (https://miktex.org/download; say yes to automatic package installation) on Windows, and sudo apt install texlive texlive-latex-extra texlive-fonts-recommended on Ubuntu/Debian (texlive-full if disk space is no object).

To confirm that a LaTeX engine is available, run quarto check in a terminal and look for the “LaTeX” line, or in R:

tinytex::is_tinytex()          # TRUE if TinyTeX is installed
Sys.which("pdflatex")          # path to the engine (empty if none is found)

VS Code

Download Visual Studio Code from https://code.visualstudio.com/download. It is free and requires no account. Run the installer, open VS Code, and allow any permissions it asks for. Installation details and the extensions we use are in Section 2.4.

Positron

Download Positron from https://positron.posit.co/download and run the installer. Positron discovers the R and Python installations on your computer when it starts, so if you install R or Python after Positron, quit and reopen it and they will appear in the interpreter picker at the top right. Two things make Positron the right first install: its terminal panel (Ctrl-`) is where all the shell work in Chapter 4 happens, and it bundles Quarto, so Markdown and rendering work with nothing extra. Details are in Section 2.5.

RStudio

RStudio Desktop is Posit’s classic, R-focused IDE. It is optional for this course but worth having if you already know it, and it is the environment you will meet on Talapas through Open OnDemand (Chapter 3). Download the free open-source edition from https://posit.co/download/rstudio-desktop/; the page detects your operating system and offers the right installer. On macOS, open the .dmg and drag RStudio to your Applications folder; on Windows, run the installer with the defaults; on Ubuntu, download the .deb and install it with sudo apt install ./rstudio-*.deb. Install R first: RStudio finds it automatically when it starts. Details are in Section 2.6.

Compiler tools

Several R and Python packages (and nearly all Bioconductor packages) compile from source the first time you install them, which requires a working C, C++, and often Fortran compiler. Install the toolchain once now; Section 2.13 lists the errors you will see if it is missing.

macOS. Apple’s Xcode command-line tools, installed in Chapter 1 with xcode-select --install, provide clang, git, and make. They do not include a Fortran compiler, which some R packages need; if you ever see gfortran not found, install gfortran from the R for macOS tools page at https://mac.r-project.org/tools/, then relaunch your IDE.

Windows. Install Rtools from https://cran.r-project.org/bin/windows/Rtools/, choosing the version that matches your R (for example Rtools44 for R 4.4, Rtools45 for R 4.5). Rtools is for the Windows copy of R; it is separate from Ubuntu on WSL, which uses build-essential as described next.

Linux (including Ubuntu on WSL). Install the toolchain from the package manager:

sudo apt update && sudo apt install -y build-essential gfortran

build-essential provides gcc, g++, and make; gfortran covers packages with Fortran code. On Fedora or RHEL, use sudo dnf groupinstall "Development Tools" and add gcc-gfortran.

Git (later)

We will also use Git for version control, but not yet. Installing and configuring Git, and connecting it to GitHub, is done in Chapter 20, so there is nothing to do now.

2.4 Visual Studio Code

VS Code is a free, general-purpose code editor from Microsoft, built on the open-source Code OSS project. It runs on macOS, Windows, and Linux, supports essentially every programming language through extensions, and has the largest extension ecosystem and user community of any editor. It is also the editor most likely to be waiting for you on a collaborator’s machine or in a company.

Installing and opening a project

After running the installer from https://code.visualstudio.com/download, open VS Code and use File → Open Folder to open your project directory. Windows users will be prompted to install the WSL extension; accept, because it allows VS Code to work directly inside Ubuntu. Once the WSL extension is installed, typing code . in an Ubuntu terminal opens the current directory in VS Code, connected to Ubuntu.

On macOS, the code command is not on your PATH by default. Open the Command Palette (Cmd-Shift-P), type “shell command”, and run “Shell Command: Install ‘code’ command in PATH”. From then on, code . in Terminal opens the current folder, and code somefile.R opens a single file.

The layout

VS Code’s window has a handful of regions that you will use constantly. The Activity Bar runs down the far left and switches the side panel between the Explorer (a file tree of your open folder), Search (find text across the entire project), Source Control (a graphical front-end to Git, covered in Chapter 20), and Extensions. The editor occupies the center; you can open many files in tabs and split the editor to see two files side by side with Cmd-\ (macOS) or Ctrl-\ (Windows/Linux). The integrated terminal at the bottom is a full shell (zsh, bash, or, on Windows with the WSL extension, Ubuntu’s bash); toggle it with Ctrl-`, the backtick key that sits above Tab. Finally, the Command Palette, opened with Cmd-Shift-P or Ctrl-Shift-P, lets you find and run any command by typing part of its name. If you cannot remember where a menu item lives, the Command Palette is the answer.

Extensions for this course

Open the Extensions panel (Cmd-Shift-X / Ctrl-Shift-X), search for each of the following, and click Install:

  • Quarto (from Quarto), to edit, preview, and render .qmd documents
  • Python (from Microsoft), for Python language support
  • R (from REditorSupport), for R language support
  • Jupyter (from Microsoft), for notebooks and interactive Python
  • WSL (from Microsoft; Windows only), to work inside Ubuntu
  • Later in the term, Remote - SSH (from Microsoft), which lets you edit files on Talapas as if they were local (Chapter 16)

Extensions can be added and removed at any time, so start with this short list and add more as you discover a need.

Keyboard shortcuts worth memorizing

A few shortcuts account for most of the time savings in an editor. Table 2.3 lists the ones worth learning first; they work identically in Positron. A fuller list, including shell shortcuts, is in Appendix A.

Tip

The backtick (`) used to toggle the terminal is usually on the key above Tab, not the apostrophe key. Confusing the two is the most common reason the terminal “won’t open.”

2.5 Positron

Positron is a free, next-generation data-science IDE from Posit. It is built on Code OSS, the open-source core of VS Code, so everything in the previous section (Explorer, editor tabs, terminal, Command Palette, the shortcuts in Table 2.3) carries over unchanged. What Positron adds is a set of data-science panes and native support for both R and Python.

Installing

Download Positron from https://positron.posit.co/download and run the installer. Because Positron discovers the R and Python installations on your computer when it starts, install both languages first. Then open Positron, use File → Open Folder on your project, and start an R or Python session from the interpreter picker at the top right of the window. You can have several sessions open and switch among them, which is convenient for projects that mix R and Python.

The layout

In addition to the VS Code regions, Positron adds a Console, an interactive R or Python session where you can type expressions and see results immediately; a Variables pane listing every object you have created, with its type and size; a Plots pane that displays your figures and keeps a history of them; a Data Explorer that opens a data frame in a spreadsheet-like, sortable, filterable view; and a Help pane showing documentation for the function under your cursor. The recommended workflow: write code in the editor, where it is saved in a file, and send lines or selections to the console with Cmd-Enter (macOS) or Ctrl-Enter (Windows/Linux). Use the console directly only for quick experiments; anything you would want to reproduce belongs in a file.

Extensions in Positron

Positron installs extensions from Open VSX, an open extension registry, rather than from Microsoft’s Visual Studio Marketplace. Most extensions you would want (Quarto, Python, Jupyter, and many others) are available there, but a few Microsoft-only extensions are not, and Positron provides its own equivalents for the important ones. In particular, the VS Code R extension is not used in Positron: R support is built in, so do not install it.

2.6 RStudio

RStudio, also from Posit, is the IDE that most R users learned on, and it remains an excellent environment for pure R work. Its window is divided into four fixed panes: the Source editor (top-left) for scripts and Quarto documents; the Console (bottom-left) for a live R session; the Environment/History pane (top-right) listing your objects and past commands; and the Files/Plots/Packages/Help/Viewer pane (bottom-right). The workflow is the same as in Positron: write in the Source pane and send lines to the Console with Cmd-Enter / Ctrl-Enter. RStudio has Quarto rendering built in (the Render button, Cmd/Ctrl-Shift-K), an RStudio Projects system (.Rproj files) that sets the working directory for you (Section 11.2.2), and a Tools → Install Packages dialog. It runs Python through the reticulate package but is not designed for it, and it has no general extension marketplace, so this course uses it for R work only.

2.7 VS Code vs. Positron vs. RStudio: Which Should I Use?

Because Positron is built on Code OSS, VS Code and Positron share their editor, Command Palette, terminal, keyboard shortcuts, settings format, and Quarto support; both are free, cross-platform, support extensions, and can connect to remote machines over SSH. The difference is focus. Positron is built for data science: R and Python are first-class, and the Console, Variables, Plots, and Data Explorer panes are always at hand. VS Code is general-purpose: any language works through extensions, its extension library and community are the largest, and it is the tool of choice for shell scripts, configuration files, and polyglot projects. Table 2.4 summarizes the trade-offs, and Table 2.5 gives a rule of thumb.

You do not have to choose forever. VS Code and Positron share so much muscle memory that learning one means you mostly know the other, and RStudio’s panes map directly onto Positron’s; this course shows all three.

2.8 Windows: Which Side Am I On?

With WSL installed, a Windows laptop effectively runs two operating systems: Windows itself and Ubuntu. Both are useful, but it matters which one you are typing into, because they have different home directories, different views of the file system, and different commands. Table 2.6 is the map.

The rule for this course is simple: type shell commands in Ubuntu, and install R, Python, VS Code, and Positron on the Windows side. In VS Code, a green badge in the bottom-left corner reading WSL: Ubuntu tells you that the window is connected to Ubuntu; without it, the integrated terminal is PowerShell and Unix commands will mostly fail. Your Linux home directory (/home/you) lives on a virtual disk and is the fastest place to work; your Windows files are reachable from Ubuntu under /mnt/c/ (for example /mnt/c/Users/you/Documents), and Ubuntu’s files appear in Windows File Explorer under Linux in the sidebar, or at the path \\wsl$\Ubuntu\home\you. Installing Windows Terminal from the Microsoft Store gives you a nicer terminal with tabs that can open either side.

TipKeep projects in the Linux home directory

WSL and Windows share files, so you never need two copies of anything, but where a project lives affects speed. Working inside the Linux home directory (~, that is /home/you) is noticeably faster than working under /mnt/c, and case-sensitivity rules differ between the two file systems. Keep course projects in your Linux home and reach over to /mnt/c/Users/you/Downloads only when you need a file that arrived on the Windows side. If you later run R or Python inside Ubuntu, keep the project under ~/ as well; running a WSL program on files under /mnt/c is the most common cause of mysteriously slow file reading.

2.9 Jupyter Notebooks vs. Quarto Documents

Two file formats let you mix code, its output, and explanatory text in one document, and you will encounter both. A Jupyter notebook (.ipynb) is made of cells, each containing code or Markdown, and the outputs are saved inside the file alongside the code. Notebooks are enormously popular in Python, machine learning, and image analysis; they run in JupyterLab, VS Code, and Positron, and on Talapas through Open OnDemand (Chapter 3). Their drawback is that the file is stored as JSON with embedded output, which makes it hard to read as text and awkward to track in Git.

A Quarto document (.qmd) is plain text: Markdown prose with a YAML header and code chunks in R, Python, Julia, or Bash. Output is not stored in the source; it is regenerated every time you render, which is exactly what reproducibility demands, and the plain-text source is easy to read, edit, and diff in Git. Quarto renders to HTML, PDF, Word, slides, and websites (Chapter 5). You do not have to choose between the two: Quarto can render Jupyter notebooks directly with quarto render notebook.ipynb, and can use Jupyter as the engine for Python chunks in .qmd files. This course uses Quarto; many of your labs may use Jupyter, and the skills transfer.

2.10 A Preview of Python Environments

Different projects need different versions of packages, and installing everything into one Python installation eventually breaks something. The solution is an environment: an isolated set of packages for one project. Python’s built-in venv module creates one in your project folder:

python3 -m venv .venv            # create an environment in this project
source .venv/bin/activate        # turn it on (Windows PowerShell: .venv\Scripts\activate)
pip install numpy pandas         # install packages into it
deactivate                       # turn it off

While the environment is active, python and pip refer to the copies inside .venv, and packages you install go there rather than into the system Python. On Talapas you will instead use conda environments, which can manage non-Python software as well (Chapter 16); uv is a fast, modern alternative to venv and pip; and R has the same idea in the renv package. There is nothing to set up now; the point is to know the word “environment” so that it is not a surprise later.

2.11 AI Assistants Inside the Editor

Both IDEs can host an AI coding assistant. GitHub Copilot in VS Code suggests code as you type and answers questions in a chat panel; it is free for verified students through the GitHub Student Developer Pack. Positron Assistant is an AI chat built into Positron that can see your console, variables, and plots. Both are genuinely useful for explaining error messages, writing boilerplate, and learning unfamiliar syntax.

They are also confidently wrong surprisingly often. Treat every suggestion as a draft from a well-read but careless colleague: read it, run it, and make sure you understand it before it goes into your analysis. Never paste sensitive data (see the data-classification rules in Chapter 3) into an assistant, and follow the course’s AI policy: you may use these tools to learn and debug, but the work you submit must be your own. We return to AI-assisted coding, and how to use it well, in Chapter 19; there is no need to set anything up now.

2.12 Verification Checkpoint

Once everything is installed, open a terminal inside VS Code or Positron (Ctrl-`) and run the following commands:

echo $SHELL
R --version
python3 --version     # Windows PowerShell (not WSL): try  py --version
quarto --version
quarto check          # checks for R, Python, and LaTeX

Each should print a version number (or, for quarto check, a list of passing checks), not “command not found.” Then open Positron and confirm that you can start both an R console and a Python console from the interpreter picker; in the R console, sessionInfo() prints the R version, platform, and loaded packages in one place, which is exactly what you will be asked for when reporting a problem. The most complete end-to-end test is to create a new Quarto document (in VS Code or Positron, Command Palette → Quarto: New Document), set format: pdf in its header, and render it: that exercises Quarto, the language engine, and TinyTeX at once. If a command is not found, the most likely explanation is that the terminal was opened before the program was installed: a terminal only sees programs that were on the PATH when it started, so close and reopen the terminal, or restart the IDE, before doing anything else. Table 2.7 lists other common problems.

If you are still stuck, copy the exact error message as text and ask for help; Chapter 3 describes where to ask at UO and how to ask so that you get a fast answer.

2.13 Troubleshooting Common Setup Problems

Table 2.7 covers the problems that appear while installing. The following come up a little later, usually the first time you install R packages or start a real project, and every one of them has bitten several students in past years.

macOS: “compilation failed” or clang errors when installing a package

The Xcode command-line tools are missing or out of date. In Terminal:

xcode-select --install

Relaunch Positron or RStudio after the install finishes. If the error instead mentions gfortran not found or library not found for -lgfortran, install gfortran from https://mac.r-project.org/tools/ (see the compiler tools item in Section 2.3) and try the package install again.

Windows: “WARNING: Rtools is required to build R packages”

R is trying to compile a package but cannot find Rtools, or you have an Rtools version that does not match your R version (Rtools44 for R 4.4, and so on). Install the matching version from https://cran.r-project.org/bin/windows/Rtools/, restart R, and confirm with Sys.which("make"), which should now print a path.

BiocManager::install() hangs or takes forever on one package

The most common cause is a slow Bioconductor mirror. Pick a closer one and try again:

chooseBioCmirror()                              # interactive; pick a US mirror
options(BioC_mirror = "https://bioconductor.org")
BiocManager::install("DESeq2")

The first Bioconductor install compiles many dependencies and can genuinely take 20 to 60 minutes; do it the day before you need it, not the morning of.

Positron or RStudio “can’t find” a package you just installed

Almost always a stale R session: the package was installed, but the running session was started before. Restart R (Session → Restart R, or Ctrl/Cmd + Shift + F10) and try library() again. If that does not help, the package may have been installed into the library of a different R version than the one the IDE is running:

.libPaths()                          # which library folders is this session using?
installed.packages()[, "Package"]    # what is actually installed there?
R.version.string                     # which R is this?

If the versions do not match, point the IDE at the correct R install (Positron: the interpreter picker at the top right; RStudio: Tools → Global Options → General → R version) and reinstall the package there.

Windows/WSL: R or Python is painfully slow, or cannot see the project files

The project is on the Windows side (/mnt/c/Users/...) but the program is running inside WSL, or the reverse. File access across that boundary is dramatically slower, and case-sensitivity differs. Choose one arrangement and stick with it: either run R, Python, and the IDE as Windows programs with the project under C:\Users\you, which is what this course recommends (Section 2.8), or run everything inside Ubuntu with the project under ~/.

Rendering to PDF fails, or LaTeX complains about a missing .sty file

Quarto rendered your document to HTML without complaint, but format: pdf stops with an error. Read the end of the log: the message usually names the problem. If it is ! LaTeX Error: File 'something.sty' not found, TinyTeX normally installs the missing package on the fly; when it does not (typically because the package index is stale), update TinyTeX and install the package by hand, using either the terminal or the R console:

quarto update tinytex          # refresh TinyTeX and its package index
tlmgr install <package-name>   # e.g. tlmgr install fontawesome5
tinytex::tlmgr_update()
tinytex::tlmgr_install("package-name")

If quarto check reports that no LaTeX installation was found at all, TinyTeX is not installed or not on your PATH: run quarto install tinytex again (Section 2.3.5) and reopen the terminal. If the TinyTeX installer itself hangs, the usual culprit is a firewall or a campus network that blocks the CTAN mirror; try again from a different network.

Old results keep coming back after a fix

R keeps every object you create for the whole session, so a later chunk can silently use an old object after you edit an earlier one. Restart R and run the script from the top; rm(list = ls()) clears variables but not loaded packages, so a restart is more reliable. Do not save the workspace to .RData on exit (answer “no” if R asks; in RStudio, set Tools → Global Options → General → Save workspace to Never), so that each session starts clean.

2.14 Keeping Software Updated

Nothing in this chapter is install-once-and-forget. New versions bring bug fixes, security patches, and, in the case of R, access to packages that require a recent version. Once a term is a reasonable rhythm, and Table 2.8 lists how each piece is updated. Two cautions: do not update the morning of a deadline, and after a major R upgrade (for example 4.4 to 4.5) expect to reinstall your packages, because each major version keeps its own package library.

After any update, run the checkpoint commands in Section 2.12 again; a surprising number of “it worked yesterday” problems are a tool that updated itself overnight and now needs the terminal reopened or a package reinstalled.

2.15 Summary

This chapter assembled the software you will use for the rest of the course and, more importantly, introduced the place where you will do most of your work: the editor. Key takeaways:

  • An IDE combines an editor, terminal, console, and project tools in one window; always open the whole project folder, not a single file
  • The core installs are R (matching your chip), Python (with “Add to PATH” on Windows), Quarto with TinyTeX, VS Code, and Positron; Git comes later in Chapter 20
  • VS Code is general-purpose with the largest ecosystem; Positron is built on the same core with R and Python and data-science panes built in; RStudio remains a fine choice for pure R
  • On Windows, type shell commands in Ubuntu but install languages and IDEs on the Windows side, and watch for the “WSL: Ubuntu” badge
  • Quarto documents are plain text and regenerate their output; Jupyter notebooks store output in the file; Quarto can render both
  • Python environments (venv, conda, uv) and R’s renv isolate each project’s packages
  • Editor-based AI assistants are useful for learning and debugging but must be read, tested, and never fed sensitive data
  • Compiling packages needs a toolchain: Xcode command-line tools plus gfortran on macOS, Rtools matching your R version on Windows, build-essential gfortran on Linux
  • R --version, python3 --version, quarto --version, and quarto check confirm a working installation; when a command is not found, reopen the terminal first
  • The most common later problems (compiler errors, slow Bioconductor mirrors, a stale R session, missing LaTeX packages, projects on the wrong side of WSL) are collected in Section 2.13
  • Update the toolkit once a term (Table 2.8), never the morning of a deadline; a major R upgrade means reinstalling packages

In Chapter 3 we turn from your laptop to the resources the University provides: your digital identity, cloud storage, data-security rules, site-licensed software, and the Talapas cluster.
