What is a Shell Script?

  • Text file containing Unix commands
  • Automates repetitive tasks
  • Makes complex workflows reproducible
  • Essential for bioinformatics pipelines
  • Can include:
    • Variables and arrays
    • Conditionals (if/then/else)
    • Loops (for/while)
    • Functions
    • Command-line arguments

Creating Your First Script

#!/bin/bash
# This is a shebang - tells system which interpreter to use

# This is a comment - documents your code
echo "Hello, Bioengineering!"

# Set a variable
NAME="DNA Analysis"
echo "Running $NAME"

# Use command output as variable
DATE=$(date +%Y-%m-%d)
echo "Analysis date: $DATE"

# Simple calculation
COUNT=5
DOUBLE=$((COUNT * 2))
echo "Double of $COUNT is $DOUBLE"

Save as first_script.sh and run with bash first_script.sh

Making Scripts Executable

# Check current permissions
ls -l first_script.sh

# Make executable (add execute permission)
chmod +x first_script.sh

# Now you can run it directly
./first_script.sh

Best practice: Always use chmod +x for your scripts

Command-Line Arguments

#!/bin/bash
# Script: process_fasta.sh

# $0 is the script name

echo "Script name: $0"

# $# is the number of arguments

echo "Number of arguments: $#"

# Check if enough arguments provided FIRST

if [ $# -lt 2 ]; then
    echo "Usage: $0 input.fasta output.txt"
    exit 1
fi

# Now safe to use the arguments

echo "Processing file: $1"
echo "Output will be: $2"

# $@ is all arguments (should be quoted)

echo "All arguments: $@"

Run as: ./process_fasta.sh input.fa results.txt

Variables and Arrays

#!/bin/bash

# Variables (no spaces around =)
SPECIES="Homo sapiens"
CHROMOSOME=21
GENE_COUNT=234

# Arrays
BASES=(A C G T)
echo "First base: ${BASES[0]}"
echo "All bases: ${BASES[@]}"

# Add to array
BASES+=(N)

# Array length
echo "Number of bases: ${#BASES[@]}"

# String operations
FILE="sample_001.fastq.gz"
NAME="${FILE%.fastq.gz}"     # Remove suffix
echo "Sample name: $NAME"

Conditionals (if/then/else)

#!/bin/bash

# Numeric comparisons
COUNT=100
if [ $COUNT -gt 50 ]; then
    echo "High read count"
elif [ $COUNT -gt 10 ]; then
    echo "Medium read count"
else
    echo "Low read count"
fi

# String comparisons
FILETYPE="fasta"
if [ "$FILETYPE" = "fasta" ]; then
    echo "Processing FASTA file"
fi

# File tests
if [ -f "data.txt" ]; then
    echo "File exists"
fi

if [ -d "results" ]; then
    echo "Directory exists"
else
    mkdir results
fi

Test operators for [ ]

Operator Meaning Operator Meaning
-eq Equal (numbers) = Strings are equal
-ne Not equal (numbers) != Strings differ
-gt Greater than -z String is empty
-lt Less than -f File exists
-ge Greater than or equal -d Directory exists
-le Less than or equal -s File exists, not empty

Tip

Always put spaces inside the brackets ([ $x -gt 5 ], not [$x -gt 5]) and quote your variables ("$FILE") so file names with spaces don’t break your script.

Loops in Shell Scripts

#!/bin/bash

# For loop over list
for BASE in A C G T; do
    echo "Processing base: $BASE"
done

# For loop over files
for FILE in *.fasta; do
    echo "Analyzing $FILE"
    grep -c ">" "$FILE"
done

# For loop with counter
for i in {1..10}; do
    echo "Iteration $i"
done

# While loop
COUNT=1
while [ $COUNT -le 5 ]; do
    echo "Count: $COUNT"
    COUNT=$((COUNT + 1))
done

# Read file line by line
while read LINE; do
    echo "Processing: $LINE"
done < input.txt

Functions in Scripts

#!/bin/bash

# Define a function
count_sequences() {
    local FILE=$1  # Local variable
    local COUNT=$(grep -c "^>" "$FILE")
    echo "$COUNT"  # "Return" a value by printing it
}
# Note: bash 'return' only carries an exit status (0-255), not data -
# so functions hand back results via echo, captured with $(...)
n=$(count_sequences proteins.fasta)
echo "proteins.fasta has $n sequences"

# Another function with multiple parameters
process_fasta() {
    local INPUT=$1
    local OUTPUT=$2
    
    echo "Processing $INPUT..."
    grep "^>" "$INPUT" > "$OUTPUT"
    echo "$INPUT has $(count_sequences "$INPUT") sequences"
}

# Call functions
process_fasta "input.fasta" "headers.txt"

Error Handling

#!/bin/bash

# Exit on error
set -e

# Exit on undefined variable
set -u

# Pipe failure detection
set -o pipefail

# Custom error handling
check_file() {
    if [ ! -f "$1" ]; then
        echo "Error: File $1 not found!" >&2
        exit 1
    fi
}

# Trap errors
trap 'echo "Error on line $LINENO"' ERR

# Try-catch style
if ! grep "pattern" file.txt > /dev/null 2>&1; then
    echo "Pattern not found"
fi

Real Bioinformatics Script Example

#!/bin/bash
# Script: fasta_stats.sh
# Purpose: Calculate basic statistics for FASTA files

# Check arguments
if [ $# -ne 1 ]; then
    echo "Usage: $0 sequences.fasta"
    exit 1
fi

INPUT=$1

# Check if file exists
if [ ! -f "$INPUT" ]; then
    echo "Error: File $INPUT not found!"
    exit 1
fi

echo "=== FASTA Statistics for $INPUT ==="

# Count sequences
SEQ_COUNT=$(grep -c "^>" "$INPUT")
echo "Number of sequences: $SEQ_COUNT"

# Calculate total length
TOTAL_LENGTH=$(grep -v "^>" "$INPUT" | tr -d '\n' | wc -c)
echo "Total length: $TOTAL_LENGTH bp"

# Average length
AVG_LENGTH=$((TOTAL_LENGTH / SEQ_COUNT))
echo "Average length: $AVG_LENGTH bp"

# GC content
GC_COUNT=$(grep -v "^>" "$INPUT" | tr -d '\n' | grep -o "[GC]" | wc -l)
GC_PERCENT=$((GC_COUNT * 100 / TOTAL_LENGTH))
echo "GC content: $GC_PERCENT%"

The same script in R and Python

The shell version of fasta_stats.sh works, but counting and arithmetic get awkward in bash. Here is the same program as an R script and a Python script - both take the file name as a command-line argument.

  • R
  • Python
#!/usr/bin/env Rscript
# Script: fasta_stats.R
# Purpose: Calculate basic statistics for a FASTA file

args <- commandArgs(trailingOnly = TRUE)     # like $1 $2 ... in bash
if (length(args) != 1) {
  cat("Usage: Rscript fasta_stats.R sequences.fasta\n")
  quit(status = 1)
}
input <- args[1]
if (!file.exists(input)) {
  cat("Error: File", input, "not found!\n")
  quit(status = 1)
}

lines   <- readLines(input)
headers <- grepl("^>", lines)                # TRUE for header lines
seq     <- paste(lines[!headers], collapse = "")

cat("=== FASTA Statistics for", input, "===\n")
cat("Number of sequences:", sum(headers), "\n")
cat("Total length:", nchar(seq), "bp\n")
cat("Average length:", nchar(seq) / sum(headers), "bp\n")
gc <- sum(strsplit(seq, "")[[1]] %in% c("G", "C"))
cat("GC content:", round(100 * gc / nchar(seq), 1), "%\n")
#!/usr/bin/env python3
# Script: fasta_stats.py
# Purpose: Calculate basic statistics for a FASTA file

import sys
from pathlib import Path

if len(sys.argv) != 2:                       # sys.argv[0] is the script name, like $0
    print("Usage: python3 fasta_stats.py sequences.fasta")
    sys.exit(1)
input_file = Path(sys.argv[1])
if not input_file.is_file():
    print(f"Error: File {input_file} not found!")
    sys.exit(1)

lines   = input_file.read_text().splitlines()
headers = [line for line in lines if line.startswith(">")]
seq     = "".join(line for line in lines if not line.startswith(">"))

print(f"=== FASTA Statistics for {input_file} ===")
print(f"Number of sequences: {len(headers)}")
print(f"Total length: {len(seq)} bp")
print(f"Average length: {len(seq) / len(headers):.1f} bp")
gc = seq.count("G") + seq.count("C")
print(f"GC content: {100 * gc / len(seq):.1f}%")

Running R and Python scripts from the shell

  • R
  • Python
Rscript fasta_stats.R proteins.fasta        # run with the interpreter ...

chmod +x fasta_stats.R                      # ... or make it executable
./fasta_stats.R proteins.fasta              #     (needs the #!/usr/bin/env Rscript shebang)

Rscript -e 'mean(c(1, 2, 3))'               # one-liner without a file
R                                           # interactive console; quit with q()
  • Rscript runs the file top to bottom and prints only what you cat() or print()
  • In RStudio / Positron: open the .R file and press Cmd/Ctrl-Enter to send lines to the console
python3 fasta_stats.py proteins.fasta       # run with the interpreter ...

chmod +x fasta_stats.py                     # ... or make it executable
./fasta_stats.py proteins.fasta             #     (needs the #!/usr/bin/env python3 shebang)

python3 -c 'print(sum([1, 2, 3]) / 3)'      # one-liner without a file
python3                                     # interactive REPL; quit with exit() or Ctrl-D
  • python3 script.py runs the file top to bottom and prints only what you print()
  • In VS Code / Positron: open the .py file and press Cmd/Ctrl-Enter, or use the Run button
  • Keep project packages in a virtual environment: python3 -m venv .venv && source .venv/bin/activate

Tip

Both scripts return an exit status (quit(status = 1) / sys.exit(1)), so a shell pipeline or SLURM job can tell whether they succeeded - just like exit 1 in bash. In Lecture 10 we submit these scripts to Talapas with Rscript and python3 inside an sbatch job.

Best Practices for Shell Scripts

  1. Always include a shebang: #!/bin/bash
  2. Comment your code: Explain what and why
  3. Use meaningful variable names: GENE_COUNT not GC
  4. Check inputs: Validate files exist and arguments are correct
  5. Handle errors gracefully: Use set -e and error checking
  6. Make scripts portable: Don’t hardcode paths
  7. Use version control: Track changes with git
  8. Test incrementally: Build scripts step by step
  9. Create help messages: Document usage
  10. Log important steps: Keep records of what was done

Note

Every one of these applies to R and Python scripts too: shebang line, comments, checking commandArgs() / sys.argv, meaningful names, relative paths, Git, and testing on a tiny input first.
