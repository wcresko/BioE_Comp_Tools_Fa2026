GREP and Regular Expressions - finishing from L03

Reminder: grep finds lines that match a pattern

grep [options] pattern [file...]
  • GREP = Global Regular Expression Print - reads lines, prints the ones that match
  • The flags you will use constantly:
    • -i ignore case · -c count matching lines · -n show line numbers
    • -v invert (print lines that do not match) · -w match whole words only
    • -o print only the matching text · -E extended regex (alternation, +, {n,m})
  • The pattern is a regular expression:
    • ^ start of line · $ end of line · . any one character
    • [ACGT] one character from the set · [^ACGT] one character not in the set
    • * zero or more · + one or more (-E) · \{3\} exactly 3 (or {3} with -E)
    • (ATG|GTG|TTG) grouping and alternation with -E
  • Full treatment: the L03 slides, Ch. 9 and App. D

Reminder: grep lives in pipelines

# Count sequences in a FASTA file (headers start with >)
grep -c "^>" proteins.fasta

# Skip comments, pull one column, tally the unique values
grep -v "^#" annotation.gff | cut -f3 | sort | uniq -c

# Most genomic data is gzip-compressed - zgrep/zcat read .gz directly
zgrep -c "^>" chr21.fa.gz
zcat reads.fastq.gz | awk 'NR % 4 == 2' | grep -c "N"

# Print only the matching text, not the whole line
grep -oE "gene=[^;]+" annotation.gff | head

Note

From L03: FASTA = > header + sequence lines; FASTQ = 4 lines per read; zcat / zless / zgrep read compressed files without unpacking them.

Warm-up quiz: which lines match?

The file test.txt has four lines:

ATGCCCTAG
CCATG
ATG
ACG

Predict the output of each command before you run it:

grep "^ATG" test.txt
grep "ATG$" test.txt
grep "^A.G$" test.txt
  • ^ATG → lines 1 and 3 (must start with ATG)
  • ATG$ → lines 2 and 3 (must end with ATG)
  • ^A.G$ → lines 3 and 4 (exactly three characters: A, anything, G)

streams and grep on the stickleback table


# Keep only the header plus the mono-associated fish, save to a new file
head -n 1 data/Stickle_RNAseq.tsv > results/mono.tsv
grep -w "mono" data/Stickle_RNAseq.tsv >> results/mono.tsv
wc -l results/mono.tsv                        

# Which individuals are genotype B raised conventionally?
grep -w "convB" data/Stickle_RNAseq.tsv | cut -f 1

# A regular expression: individuals whose ID ends in a 1
grep -E "^[A-Z]+1\b" data/Stickle_RNAseq.tsv | cut -f 1-3

# Send errors somewhere useful: a typo in the path goes to the log, not the screen
grep -w "mono" data/Stickle_RNAseq.tsv 2> results/errors.log; cat results/errors.log

Tip

  • > creates the file, >> appends to it, 2> captures stderr.
  • grep -w "mono" matches mono only as a whole word, so it finds the 40 mono-associated fish through the third column but would not match monoA on its own.
  • Try grep -c mono versus grep -cw mono: both give 40 here.
  • Work out why (which column does each one match on?) - experiments like this are how you learn what a flag really does.

Worked Example - Downloading and Exploring a Large Genomic File

Human Chromosome Data

  • Everything so far - reading files, pipes, redirection, grep - in one realistic job: grab a big public dataset and ask it questions, straight from the shell

  • Genomic data files can be massive (the full human genome is ~3.1 GB compressed)

  • FASTA format is standard for sequence data

  • Perfect use case for Unix pipes and redirection

  • We will practice on human chromosome 21 - the smallest autosome (~13 MB compressed, ~46 Mb of sequence), so every command finishes in seconds

  • The same commands work unchanged on the whole genome - only the wait time changes

  • The course book works through the same file in Chapter 9

Downloading Genomic Data

Download chromosome 21 of the human genome (hg38 / GRCh38) from UCSC:

# Using `wget` to download chr21 (~13 MB)

wget https://hgdownload.soe.ucsc.edu/goldenPath/hg38/chromosomes/chr21.fa.gz

# Or using `curl` and save with a specific name (-L follows redirects)

curl -L -o chr21.fa.gz \
  https://hgdownload.soe.ucsc.edu/goldenPath/hg38/chromosomes/chr21.fa.gz
  • wget and curl are both tools for downloading files (macOS ships curl; install wget with Homebrew if you want it)
  • The backslash lets a long command span multiple lines
  • .gz extension means the file is compressed
  • The whole genome lives in the same directory as hg38.fa.gz (~1 GB) - same commands, much longer runs

Examining Large Files Efficiently

Don’t use cat on huge files! Use these approaches:

# Decompress and look at first 10 lines

gunzip -c chr21.fa.gz | head -10

# Check file size before and after decompression (-k keeps the .gz)

ls -lh chr21.fa.gz
gunzip -k chr21.fa.gz
ls -lh chr21.fa

# Count sequences in FASTA file (lines starting with >)
# grep can't read gzip data directly - use zgrep (or zcat | grep)

zgrep "^>" chr21.fa.gz | wc -l

# View sequence headers only

zgrep "^>" chr21.fa.gz | less

Note

  • The UCSC file is soft-masked: repeats are written in lowercase (acgt).
  • Patterns like GAATTC will miss sites inside masked regions - add -i to grep
  • Or uppercase everything first with tr 'acgt' 'ACGT'.

Creating a Subset for Analysis

Make a smaller working file for testing:

# Extract the first ~1 Mb of sequence for testing (50 bases per line)

zcat chr21.fa.gz | head -n 20000 > chr21_subset.fa

# Extract a specific record by name from a multi-sequence FASTA
# (e.g. from hg38.fa - chr21.fa has only one record)

awk '/^>chr21$/,/^>chr22$/' hg38.fa | head -n -1 > chr21_from_genome.fa

# Pull out a window of lines from the middle of the chromosome

sed -n '400000,420000p' chr21.fa > region_of_interest.fa

Note

awk and sed get their full treatment later today - read those two lines as recipes for now.

Processing FASTA Files with Pipes

Extract specific regions or sequences:

# Extract just the sequence (no headers) and count bases

grep -v "^>" chr21.fa | tr -d '\n' | wc -c

# Count each type of nucleotide (uppercase first so a == A)

grep -v "^>" chr21.fa | \
  tr 'acgtn' 'ACGTN' | \
  tr -d '\n' | \
  fold -w1 | \
  sort | \
  uniq -c
  • grep -v inverts the match (excludes lines)
  • tr -d '\n' removes newlines
  • fold -w1 puts each character on its own line
  • Expect a lot of N - the first ~5 Mb of chr21 is unassembled

Finding Patterns in Genomic Data

Search for specific sequences and motifs:

# Find all instances of a restriction enzyme site (EcoRI: GAATTC)

grep -v "^>" chr21.fa | \
  tr 'acgt' 'ACGT' | \
  tr -d '\n' | \
  grep -o "GAATTC" | \
  wc -l

# Extract 100 bases around each EcoRI site

grep -v "^>" chr21.fa | \
  tr 'acgt' 'ACGT' | \
  tr -d '\n' | \
  grep -oE ".{100}GAATTC.{100}" > ecori_contexts.txt

# Find all start codons (ATG) and their byte offsets

grep -v "^>" chr21.fa | \
  tr 'acgt' 'ACGT' | \
  tr -d '\n' | \
  grep -b -o "ATG" | \
  head -20

Combining Downloads with Processing

Stream processing without saving intermediate files:

# Download, decompress, and process in one pipeline
curl -sL https://hgdownload.soe.ucsc.edu/goldenPath/hg38/chromosomes/chr21.fa.gz | \
  gunzip -c | \
  grep -v "^>" | \
  tr -d '\n' | \
  cut -c1-1000000 > first_megabase.txt

# Download and immediately analyze GC content
wget -qO - https://hgdownload.soe.ucsc.edu/goldenPath/hg38/chromosomes/chr21.fa.gz | \
  gunzip -c | \
  grep -v "^>" | \
  tr 'acgtn' 'ACGTN' | \
  tr -d 'N\n' | \
  tr 'ATGC' '0011' | \
  awk '{n = length($0); gc = gsub(/1/, ""); print "GC%:", 100 * gc / n}'
  • The -O - flag tells wget to output to stdout
  • This approach saves disk space and time

Your turn: sequence content of chr21

Using only commands you now know (grep -v, tr, fold, sort, uniq, wc):

  1. Count the total number of bases in chr21.fa
  2. Calculate the GC content (percent of bases that are G or C)
  3. Find runs of the dinucleotide repeat AT five or more units long
  4. Bonus: what fraction of the chromosome is N?

Tip

Build each pipeline one command at a time and check the output at every stage. Remember the soft-masking: uppercase first with tr 'acgt' 'ACGT'.

Solutions:

  • Total bases: grep -v “^>” chr21.fa | tr -d ‘’ | wc -c
  • GC content: grep -v “^>” chr21.fa | tr -d ‘’ | tr -cd ‘GCgc’ | wc -c, divided by the total
  • Repeats: grep -v “^>” chr21.fa | tr ‘acgt’ ‘ACGT’ | tr -d ‘’ | grep -oE “(AT){5,}”
  • N fraction: same pipeline with tr -cd ‘Nn’ | wc -c, divided by the total

Takeaways from the worked example

  • Real bioinformatics often involves gigabytes of data - these Unix tools scale beautifully!
  • Never load entire genome files into memory - use streaming
  • Combine tools - each does one thing well
  • Test on subsets first - extract small portions for development
  • Use compression - work with .gz files directly when possible
  • Think in streams - data flows through pipes without intermediate files
  • Document your pipelines - save commands in scripts … which is the rest of today

What is a Shell Script?

  • Text file containing Unix commands
  • Automates repetitive tasks
  • Makes complex workflows reproducible
  • Essential for bioinformatics pipelines
  • Can include:
    • Variables and arrays
    • Conditionals (if/then/else)
    • Loops (for/while)
    • Functions
    • Command-line arguments

Creating Your First Script

#!/bin/bash
# This is a shebang - tells system which interpreter to use

# This is a comment - documents your code
echo "Hello, Bioengineering!"

# Set a variable
NAME="DNA Analysis"
echo "Running $NAME"

# Use command output as variable
DATE=$(date +%Y-%m-%d)
echo "Analysis date: $DATE"

# Simple calculation
COUNT=5
DOUBLE=$((COUNT * 2))
echo "Double of $COUNT is $DOUBLE"

Save as first_script.sh and run with bash first_script.sh

Making Scripts Executable

# Check current permissions
ls -l first_script.sh

# Make executable (add execute permission)
chmod +x first_script.sh

# Now you can run it directly
./first_script.sh

Best practice: Always use chmod +x for your scripts

Command-Line Arguments

#!/bin/bash
# Script: process_fasta.sh

# $0 is the script name

echo "Script name: $0"

# $# is the number of arguments

echo "Number of arguments: $#"

# Check if enough arguments provided FIRST

if [ $# -lt 2 ]; then
    echo "Usage: $0 input.fasta output.txt"
    exit 1
fi

# Now safe to use the arguments

echo "Processing file: $1"
echo "Output will be: $2"

# $@ is all arguments (should be quoted)

echo "All arguments: $@"

Run as: ./process_fasta.sh input.fa results.txt

Variables and Arrays

#!/bin/bash

# Variables (no spaces around =)
SPECIES="Homo sapiens"

Conditionals (if/then/else)

#!/bin/bash

# Numeric comparisons
COUNT=100
if [ $COUNT -gt 50 ]; then
    echo "High read count"
elif [ $COUNT -gt 10 ]; then
    echo "Medium read count"
else
    echo "Low read count"
fi

# String comparisons
FILETYPE="fasta"
if [ "$FILETYPE" = "fasta" ]; then
    echo "Processing FASTA file"
fi

# File tests
if [ -f "data.txt" ]; then
    echo "File exists"
fi

if [ -d "results" ]; then
    echo "Directory exists"
else
    mkdir results
fi

Test operators for [ ]

Operator Meaning Operator Meaning
-eq Equal (numbers) = Strings are equal
-ne Not equal (numbers) != Strings differ
-gt Greater than -z String is empty
-lt Less than -f File exists
-ge Greater than or equal -d Directory exists
-le Less than or equal -s File exists, not empty

Tip

Always put spaces inside the brackets ([ $x -gt 5 ], not [$x -gt 5]) and quote your variables ("$FILE") so file names with spaces don’t break your script.

Loops in Shell Scripts

#!/bin/bash

# For loop over list
for BASE in A C G T; do
    echo "Processing base: $BASE"
done

# For loop over files
for FILE in *.fasta; do
    echo "Analyzing $FILE"
    grep -c ">" "$FILE"
done

# For loop with counter
for i in {1..10}; do
    echo "Iteration $i"
done

# While loop
COUNT=1
while [ $COUNT -le 5 ]; do
    echo "Count: $COUNT"
    COUNT=$((COUNT + 1))
done

# Read file line by line
while read LINE; do
    echo "Processing: $LINE"
done < input.txt

Functions in Scripts

#!/bin/bash

# Define a function
count_sequences() {
    local FILE=$1  # Local variable
    local COUNT=$(grep -c "^>" "$FILE")
    echo "$COUNT"  # "Return" a value by printing it
}
# Note: bash 'return' only carries an exit status (0-255), not data -
# so functions hand back results via echo, captured with $(...)
n=$(count_sequences proteins.fasta)
echo "proteins.fasta has $n sequences"

# Another function with multiple parameters
process_fasta() {
    local INPUT=$1
    local OUTPUT=$2
    
    echo "Processing $INPUT..."
    grep "^>" "$INPUT" > "$OUTPUT"
    echo "$INPUT has $(count_sequences "$INPUT") sequences"
}

# Call functions
process_fasta "input.fasta" "headers.txt"

Error Handling

#!/bin/bash

# Exit on error
set -e

# Exit on undefined variable
set -u

# Pipe failure detection
set -o pipefail

# Custom error handling
check_file() {
    if [ ! -f "$1" ]; then
        echo "Error: File $1 not found!" >&2
        exit 1
    fi
}

# Trap errors
trap 'echo "Error on line $LINENO"' ERR

# Try-catch style
if ! grep "pattern" file.txt > /dev/null 2>&1; then
    echo "Pattern not found"
fi

Two more tools for scripts: sed and awk

Editing streams inside a script

Shell scripts rarely do arithmetic or text editing themselves - they glue together small tools. Two of the most useful in a pipeline are sed (edit text as it streams past) and awk (work with columns). You met grep last week; these complete the trio.

Beyond grep: sed for search-and-replace

# Substitute the first match on each line (s/pattern/replacement/)
sed 's/chr/Chr/' regions.bed

# Substitute every match on each line (g = global)
sed 's/T/U/g' dna.txt > rna.txt

# Delete lines matching a pattern (e.g. comment lines)
sed '/^#/d' annotation.gff

# Print only lines 10-20
sed -n '10,20p' big_file.txt

Warning

sed -i edits a file in place - and the syntax differs between Linux (sed -i 's/a/b/' f) and macOS (sed -i '' 's/a/b/' f). Write to a new file until you’re confident.

Beyond grep: awk for columns

# Print columns 1 and 3 of a tab- or space-separated file
awk '{print $1, $3}' data.tsv

# Keep rows where column 5 is greater than 30
awk '$5 > 30' measurements.tsv

# Comma-separated file: set the field separator, skip the header
awk -F',' 'NR > 1 {print $2}' samples.csv

# Sum and average a column
awk -F',' 'NR > 1 {sum += $3; n++} END {print sum, sum/n}' samples.csv

Tip

Rule of thumb: grep finds lines, sed edits text, awk works with columns. More in the course book’s sed and awk sections and Regular Expression Reference.

Running example: sed, awk and a script on the stickleback table

cd ~/projects/comptools && mkdir -p results

# Fix the awkward column name once, writing a new file (never edit raw data in place)
sed '1s/Geno&Micro/Geno_Micro/' data/Stickle_RNAseq.tsv > results/stickle_clean.tsv

# Mean of Gene1 (column 5) across all 80 fish
awk -F'\t' 'NR > 1 { sum += $5; n++ } END { print "Gene1 mean:", sum/n }' results/stickle_clean.tsv

# Mean of Gene1 by genotype - awk arrays keyed by the group
awk -F'\t' 'NR > 1 { sum[$2] += $5; n[$2]++ } END { for (g in sum) print g, sum[g]/n[g] }' results/stickle_clean.tsv

Turn it into a script

#!/bin/bash
# gene_means.sh - mean count of one gene per treatment group
# Usage: ./gene_means.sh <gene column number>
set -euo pipefail
col=${1:?Give a gene column number, e.g. 5 for Gene1}
infile=results/stickle_clean.tsv

gene=$(head -n 1 "$infile" | cut -f "$col")
echo "Mean of $gene by group:"
awk -F'\t' -v c="$col" 'NR > 1 { sum[$4] += $c; n[$4]++ } END { for (g in sum) printf "  %-6s %8.1f\n", g, sum[g]/n[g] }' "$infile"
chmod +x gene_means.sh
./gene_means.sh 5            # Gene1
for c in 5 6 7; do ./gene_means.sh $c; done    # loop over the first three genes

Real Bioinformatics Script Example

#!/bin/bash
# Script: fasta_stats.sh
# Purpose: Calculate basic statistics for FASTA files

# Check arguments
if [ $# -ne 1 ]; then
    echo "Usage: $0 sequences.fasta"
    exit 1
fi

INPUT=$1

# Check if file exists
if [ ! -f "$INPUT" ]; then
    echo "Error: File $INPUT not found!"
    exit 1
fi

echo "=== FASTA Statistics for $INPUT ==="

# Count sequences
SEQ_COUNT=$(grep -c "^>" "$INPUT")
echo "Number of sequences: $SEQ_COUNT"

# Calculate total length
TOTAL_LENGTH=$(grep -v "^>" "$INPUT" | tr -d '\n' | wc -c)
echo "Total length: $TOTAL_LENGTH bp"

# Average length
AVG_LENGTH=$((TOTAL_LENGTH / SEQ_COUNT))
echo "Average length: $AVG_LENGTH bp"

# GC content
GC_COUNT=$(grep -v "^>" "$INPUT" | tr -d '\n' | grep -o "[GC]" | wc -l)
GC_PERCENT=$((GC_COUNT * 100 / TOTAL_LENGTH))
echo "GC content: $GC_PERCENT%"

The same script in R and Python

The shell version of fasta_stats.sh works, but counting and arithmetic get awkward in bash. Here is the same program as an R script and a Python script - both take the file name as a command-line argument.

  • R
  • Python
#!/usr/bin/env Rscript
# Script: fasta_stats.R
# Purpose: Calculate basic statistics for a FASTA file

args <- commandArgs(trailingOnly = TRUE)     # like $1 $2 ... in bash
if (length(args) != 1) {
  cat("Usage: Rscript fasta_stats.R sequences.fasta\n")
  quit(status = 1)
}
input <- args[1]
if (!file.exists(input)) {
  cat("Error: File", input, "not found!\n")
  quit(status = 1)
}

lines   <- readLines(input)
headers <- grepl("^>", lines)                # TRUE for header lines
seq     <- paste(lines[!headers], collapse = "")

cat("=== FASTA Statistics for", input, "===\n")
cat("Number of sequences:", sum(headers), "\n")
cat("Total length:", nchar(seq), "bp\n")
cat("Average length:", nchar(seq) / sum(headers), "bp\n")
gc <- sum(strsplit(seq, "")[[1]] %in% c("G", "C"))
cat("GC content:", round(100 * gc / nchar(seq), 1), "%\n")
#!/usr/bin/env python3
# Script: fasta_stats.py
# Purpose: Calculate basic statistics for a FASTA file

import sys
from pathlib import Path

if len(sys.argv) != 2:                       # sys.argv[0] is the script name, like $0
    print("Usage: python3 fasta_stats.py sequences.fasta")
    sys.exit(1)
input_file = Path(sys.argv[1])
if not input_file.is_file():
    print(f"Error: File {input_file} not found!")
    sys.exit(1)

lines   = input_file.read_text().splitlines()
headers = [line for line in lines if line.startswith(">")]
seq     = "".join(line for line in lines if not line.startswith(">"))

print(f"=== FASTA Statistics for {input_file} ===")
print(f"Number of sequences: {len(headers)}")
print(f"Total length: {len(seq)} bp")
print(f"Average length: {len(seq) / len(headers):.1f} bp")
gc = seq.count("G") + seq.count("C")
print(f"GC content: {100 * gc / len(seq):.1f}%")

Best Practices for Shell Scripts

  1. Always include a shebang: #!/bin/bash
  2. Comment your code: Explain what and why
  3. Use meaningful variable names: GENE_COUNT not GC
  4. Check inputs: Validate files exist and arguments are correct
  5. Handle errors gracefully: Use set -e and error checking
  6. Make scripts portable: Don’t hardcode paths
  7. Use version control: Track changes with git
  8. Test incrementally: Build scripts step by step
  9. Create help messages: Document usage
  10. Log important steps: Keep records of what was done

Note

Every one of these applies to R and Python scripts too: shebang line, comments, checking commandArgs() / sys.argv, meaningful names, relative paths, Git, and testing on a tiny input first.
