Warm-up - plot stickleback data

Last week’s job, two new languages

  • You have already piped the stickleback table through grep, sed and awk, and in L03 you ran a first Python script on it.

  • Here is that job again - read the data, total the counts per fish, draw boxplots by group - as an R script and a Python script that write the figure to an SVG file.

  • R
  • Python
#!/usr/bin/env Rscript
# Script: plot_stickleback_boxplots.R
# Purpose: boxplots of total RNA-seq counts per group, written to an SVG

infile <- "data/Stickle_RNAseq.tsv"              
if (!file.exists(infile)) {
  cat("Error: File", infile, "not found!\n")
  quit(status = 1)
}

stickle <- read.delim(infile, check.names = FALSE)  # keep the name "Geno&Micro"
genes   <- grep("^Gene", names(stickle))            # which columns are genes?
totals  <- rowSums(stickle[, genes])                # one number per fish
group   <- stickle[["Geno&Micro"]]

dir.create("results", showWarnings = FALSE)
svg("results/total_counts_by_group.svg", width = 7, height = 5)
boxplot(totals ~ group,
        xlab = "Genotype x microbiota group",
        ylab = "Total reads per fish",
        main = "Stickleback gut RNA-seq: total counts by group")
invisible(dev.off())    # close the file device, quietly
cat("Wrote results/total_counts_by_group.svg\n")
#!/usr/bin/env python3
# Script: plot_stickleback_boxplots.py
# Purpose: boxplots of total RNA-seq counts per group, written to an SVG

import sys
from pathlib import Path

import pandas as pd
import matplotlib
matplotlib.use("Agg")                 # draw straight to a file - no window
import matplotlib.pyplot as plt

infile = Path("data/Stickle_RNAseq.tsv")         
if not infile.is_file():
    print(f"Error: File {infile} not found!")
    sys.exit(1)

stickle = pd.read_csv(infile, sep="\t")
genes   = [c for c in stickle.columns if c.startswith("Gene")]
totals  = pd.DataFrame({
    "Group": stickle["Geno&Micro"],
    "Total": stickle[genes].sum(axis=1),          # one number per fish
})

Path("results").mkdir(exist_ok=True)
totals.boxplot(column="Total", by="Group")
plt.suptitle("")                      # drop pandas' default super-title
plt.title("Stickleback gut RNA-seq: total counts by group")
plt.xlabel("Genotype x microbiota group")
plt.ylabel("Total reads per fish")
plt.savefig("results/total_counts_by_group.svg")  # .svg picks the format
print("Wrote results/total_counts_by_group.svg")

R and Python

Why use R?

  • Good general scripting tool for statistics and mathematics
  • Powerful and flexible and free
  • Runs on all computer platforms
  • New enhancements coming out all the time
  • Superb data management & graphics capabilities
  • Reproducibility - can keep your scripts to see exactly what was done
  • You can write your own functions
  • Lots of online help available
  • Can use a nice IDE such as Positron
  • Can embed your R analyses in dynamic, polished files using Quarto Markdown
  • Quarto Markdown can be reused for websites, papers, books, presentations…

Why use Python?

  • A general-purpose language that is also excellent for data analysis (pandas, numpy, matplotlib, scipy)
  • The language of machine learning, image analysis and instrument control (scikit-learn, PyTorch, scikit-image)
  • Free, open source, runs everywhere - including Talapas (module load python3)
  • Huge ecosystem: pip install gives you access to >500,000 packages on PyPI; conda adds compiled scientific tools
  • Readable syntax; indentation is the structure of the code
  • Runs as scripts (python3 script.py), interactively (REPL / IPython), in Jupyter notebooks, and in Quarto {python} chunks
  • Same IDE: Positron (and VS Code) runs R and Python side by side

Tip

  • You do not have to choose. Most computational biologists use both:

    • R for statistics and figures

    • Python for pipelines, images and machine learning.

  • This lecture shows every idea in both languages - use the tabs.

Comments, names and style

  • Comments start with # and run to the end of the line - in bash, R and Python
  • Both languages are case sensitive: Weight, weight and WEIGHT are three different names
  • Legal names: letters, digits, _ (and . in R); must not start with a digit
  • Style: use snake_case, short but descriptive - mean_gc, n_fish, total_reads
  • Assigning to an existing name silently overwrites it - a frequent source of bugs
# This line is a comment in both languages
n_fish <- 80          # so is everything after the code
n_fish
[1] 80

Assigning variables

  • Assign values with <- in R and = in Python
  • R also accepts = for assignment, but course (and community) style is <-

Comparisons and logical values

  • Comparisons ask questions about values and return a logical (R) or bool (Python) - the foundation of filtering and indexing later today
  • R
  • Python

# True
not (x > 3)            # NOT is the word "not"
# False
  • R spells the logical values TRUE / FALSE; Python capitalizes only the first letter: True / False
  • R uses the symbols &, |, !; Python uses the words and, or, not (the symbols & and | are reserved for element-wise work on numpy arrays and pandas columns)

STRINGS

  • Variables and operations can be performed on characters as well
  • Note that characters need to be set off by quotation marks to differentiate them from numbers
  • The c stands for concatenate; in Python square brackets [ ] build a list
  • Note that we are using the same variable names as we did previously, which means that we’re overwriting our previous assignment
  • A good rule of thumb is to use new names for each variable, and make them short but still descriptive

  • Python

VECTORS

  • In general R thinks in terms of vectors (a list of characters, factors or numerical values).
  • It will benefit any R user to try to write programs with that in mind, as it will simplify most things.
  • Vectors can be assigned directly using the c() function and then entering the exact values.
  • Python has lists ([ ]) for any collection, and numpy arrays (np.array()) when you want R-style vector math
  • x^2 squares every element of an R vector; in Python that only works on a numpy array - a list needs a loop or a list comprehension

  • Many functions exist to operate on vectors.
  • Combine these with your previous variable to see what happens.

  • Python

import numpy as np

x.mean()                     # or np.mean(x)

  • Arguments simply modify or direct the function in some way
  • There are many arguments for each function, some of which are defaults

Data types in R and Python

Scales of measurement

Scale What it is Example Typical computer type
Nominal (categorical) Unordered labels genotype A / B; apples, oranges character or factor
Ordinal (categorical) Ordered labels small < medium < large ordered factor
Discrete (quantitative) Whole-number counts RNA-seq reads per gene integer
Continuous (quantitative) Measurements mass (kg), length (mm) double / float
  • Among continuous scales:
    • a ratio scale has a true zero (mass, length, counts);
    • an interval scale does not (temperature in °C, calendar year)
  • Factor is R’s special type for categorical variables - we will explore it more later

The same types, two sets of names

What it holds R (tibble code) Python Example
TRUE / FALSE logical (lgl) bool TRUE / True
Whole numbers integer (int) int 3L / 3
Real numbers double (dbl) float 3.0, 2.5e-3
Text character (chr) str "low"
Categories factor (fctr) pandas.Categorical factor(c("low","high"))
Dates / date-times date / dttm datetime.date / datetime.datetime as.Date("2026-11-09")
  • Integer and double vectors are known collectively as numeric vectors; in R numbers are doubles by default
  • Python keeps int and float strictly apart:
    • 7 / 2 is 3.5 (always a float)
    • 7 // 2 is 3 (integer division)
    • 7 % 2 is the remainder 1
  • R’s integer division and remainder are %/% and %%

Converting between types

  • Python

One type per vector: coercion

  • An R vector holds exactly one type - mix types and R silently coerces everything to the most flexible one: logical → integer → double → character
  • R
  • Python
c(1, 2, 3)            # double
[1] 1 2 3
c(1, 2, "three")      # one string turns ALL of them into strings
[1] "1"     "2"     "three"
c(1, 2, TRUE)         # TRUE quietly becomes 1
[1] 1 2 1
sum(c(TRUE, TRUE, FALSE, TRUE))   # ... which is genuinely useful: counting!
[1] 3
[1, 2, "three"]            # a list happily mixes types - no coercion
# [1, 2, 'three']
import numpy as np
np.array([1, 2, "three"])  # a numpy array coerces, just like R

import pandas as pd

Indexing

Indexing vectors and lists

  • R
  • Python
x <- c(2, 3, 4, 2, 1, 2, 4, 5, 10, 8, 9)
x[1]            # the FIRST element - R counts from 1
[1] 2
x[c(1, 3)]      # elements 1 and 3
[1] 2 4
x[2:4]          # elements 2 through 4 (both ends included)
[1] 3 4 2
x[-1]           # everything EXCEPT element 1
 [1]  3  4  2  1  2  4  5 10  8  9
x[x > 4]        # logical indexing: elements where the condition is TRUE
[1]  5 10  8  9
import numpy as np
x = np.array([2, 3, 4, 2, 1, 2, 4, 5, 10, 8, 9])
x[0]            # the FIRST element - Python counts from 0
# 2
x[[0, 2]]       # elements at positions 0 and 2
# [2 4]
x[1:4]          # positions 1, 2, 3 - the stop position is EXCLUDED
# [3 4 2]
x[-1]           # the LAST element (negative = count from the end)
# 9
x[x > 4]        # logical (boolean) indexing, exactly like R
# [ 5 10  8  9]
  • The same [ ] syntax, two opposite conventions: R is 1-based and inclusive, Python is 0-based and stop-excluded
  • Negative numbers drop elements in R but count from the end in Python - the classic cross-language bug
  • Logical indexing (x[x > 4]) is identical in both - and it is the idea behind filtering tables, next

Indexing a data set: rows and single cells

Both languages use table[row, column] - the differences are the starting number and labels vs positions:

  • R
  • Python
stickle[1, 1:4]            # first row, first four columns
  Individual Genotype   Microbiota Geno&Micro
1        AC1        A conventional      convA
stickle[1:3, c("Individual", "Genotype")]   # rows 1-3 of two named columns
  Individual Genotype
1        AC1        A
2        AC2        A
3        AC3        A
stickle[3, "Genotype"]     # one single cell, by row number and column name
[1] "A"
stickle[3, 2]              # the same cell, by position
[1] "A"
stickle.iloc[0, 0:4]       # first row, first four columns - by POSITION (0-based)
stickle.loc[0:2, ["Individual", "Genotype"]]   # by LABEL (row labels here are 0,1,2)
stickle.loc[2, "Genotype"]     # one single cell: row label 2, column "Genotype"
# 'A'
stickle.iloc[2, 1]             # the same cell, by position
# 'A'
  • R has one bracket for both jobs; pandas splits them: .loc[ ] for labels, .iloc[ ] for positions
  • Careful: .loc[0:2] includes both ends (label slicing), while .iloc[0:2] excludes the stop - position slicing behaves like the rest of Python

What can you read and write?

Format R Python
CSV / TSV (plain text) read.csv() / write.csv() pd.read_csv() / .to_csv()
Excel .xlsx readxl::read_excel() / writexl pd.read_excel() / .to_excel()
Plain text, line by line readLines() / writeLines() Path.read_text(), open()
JSON jsonlite::fromJSON() json.load(), pd.read_json()
Native binary objects saveRDS() / readRDS() pickle
Big columnar data arrow::read_parquet() pd.read_parquet()
  • Plain-text formats (CSV/TSV) are the default: portable, future-proof, readable by grep/awk, and diff-able in Git
  • Binary formats (.rds, .pickle, .parquet) are faster and preserve types exactly - but only their own language (or ecosystem) can read them
  • Excel files are for exchanging with humans; convert to CSV/TSV before analysis when you can (remember the gene-name-to-date horror stories)

grep and regular expressions in R and Python

The same patterns, new functions

Job Shell (L04) R Python (import re)
Which elements match? grep grepl() (TRUE/FALSE), grep() (positions) re.search()
Pull out the match grep -o regmatches() + gregexpr() re.findall()
Substitute sed 's/a/b/' sub() (first), gsub() (all) re.sub()
Split on a pattern awk -F strsplit() re.split()
  • The patterns themselves are the same ones you learned in L04: ^ start, $ end, [ACGT] classes, {3} counts, ( | ) alternatives
  • Two escaping dialects:
    • R needs a double backslash ("\\d" for a digit)
    • Python uses raw strings (r"\d") - always write Python patterns with the r prefix
  • The tidyverse’s stringr (str_detect(), str_replace(), …) wraps R’s functions with consistent names

The L04 fasta_stats bash script in R and Python

  • R
  • Python
#!/usr/bin/env Rscript
# Script: fasta_stats.R
# Purpose: Calculate basic statistics for a FASTA file

args <- commandArgs(trailingOnly = TRUE)     # like $1 $2 ... in bash
if (length(args) != 1) {
  cat("Usage: Rscript fasta_stats.R sequences.fasta\n")
  quit(status = 1)
}
input <- args[1]
if (!file.exists(input)) {
  cat("Error: File", input, "not found!\n")
  quit(status = 1)
}

lines   <- readLines(input)
headers <- grepl("^>", lines)                # TRUE for header lines
seq     <- paste(lines[!headers], collapse = "")

cat("=== FASTA Statistics for", input, "===\n")
cat("Number of sequences:", sum(headers), "\n")
cat("Total length:", nchar(seq), "bp\n")
cat("Average length:", nchar(seq) / sum(headers), "bp\n")
n_count <- sum(strsplit(seq, "")[[1]] %in% c("N", "n"))
cat("N bases:", n_count, "\n")
gc <- sum(strsplit(toupper(seq), "")[[1]] %in% c("G", "C"))
cat("GC content:", round(100 * gc / nchar(seq), 1), "%\n")
orfs <- regmatches(seq, gregexpr("ATG([ACGT]{3}){20,}(TAA|TAG|TGA)", seq))[[1]]
cat("ORF-like stretches:", length(orfs), "\n")
#!/usr/bin/env python3
# Script: fasta_stats.py
# Purpose: Calculate basic statistics for a FASTA file

import re
import sys
from pathlib import Path

if len(sys.argv) != 2:                       # sys.argv[0] is the script name, like $0
    print("Usage: python3 fasta_stats.py sequences.fasta")
    sys.exit(1)
input_file = Path(sys.argv[1])
if not input_file.is_file():
    print(f"Error: File {input_file} not found!")
    sys.exit(1)

lines   = input_file.read_text().splitlines()
headers = [line for line in lines if line.startswith(">")]
seq     = "".join(line for line in lines if not line.startswith(">"))

print(f"=== FASTA Statistics for {input_file} ===")
print(f"Number of sequences: {len(headers)}")
print(f"Total length: {len(seq)} bp")
print(f"Average length: {len(seq) / len(headers):.1f} bp")
n_count = seq.count("N") + seq.count("n")
print(f"N bases: {n_count}")
gc = seq.upper().count("G") + seq.upper().count("C")
print(f"GC content: {100 * gc / len(seq):.1f}%")
orfs = re.findall(r"ATG(?:[ACGT]{3}){20,}(?:TAA|TAG|TGA)", seq)
print(f"ORF-like stretches: {len(orfs)}")

Finale: write your own executable R and Python scripts

Anatomy of an executable script

Ingredient bash (L02-L04) R Python
Shebang (line 1) #!/bin/bash #!/usr/bin/env Rscript #!/usr/bin/env python3
Make it executable chmod +x name.sh chmod +x name.R chmod +x name.py
Run it ./name.sh ./name.R (or Rscript name.R) ./name.py (or python3 name.py)
Arguments $1, $2 commandArgs(trailingOnly = TRUE) sys.argv[1:]
Print echo cat() print()
Fail loudly exit 1 quit(status = 1) sys.exit(1)
  • The shell does not care what language is inside - the shebang tells it which interpreter to hand the file to

Summary

  • R and Python share the ideas - variables, vectors, types, indexing, files - and differ in spelling: <- vs =, ^ vs **, 1-based vs 0-based, TRUE vs True
  • A script is a text file plus a shebang, chmod +x, arguments and an exit status - in any language
  • Every vector/column has one type; know class() / type(), convert deliberately, and respect NA / NaN (and the opposite na.rm / skipna defaults)
  • Indexing: x[i], table[row, col], $ / [[ ]], .loc / .iloc - and logical tests select rows like grep selects lines
  • Files: read with read.delim() / pd.read_csv(), write results (never raw data!), save figures as vector SVG/PDF
  • Regular expressions moved with you: the L04 patterns now run inside grepl() / gsub() and re.findall() / re.sub()
