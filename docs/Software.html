Software

Software tools to install

Everything is free. Install in roughly this order; the large downloads (R, Python, VS Code, Positron, TinyTeX) can run in the background while you work through the rest. Step-by-step instructions, a verification checkpoint, and a troubleshooting table are in the course book: Chapter 1 (operating-system setup) and Chapter 2 (everything else).

  • VS Code and Positron (editors/IDEs)
  • A Unix shell (built in on Mac and Linux; WSL with Ubuntu on Windows) that can ssh to the UO computing cluster (Talapas)
  • Latest version of R
  • Python 3
  • Quarto, plus TinyTeX (a small LaTeX) for PDF output
  • Git and a GitHub account for version control and collaboration

Your laptop needs 16 GB of RAM (8 GB minimum), about 20 GB of free disk space, an up-to-date macOS, Windows 10/11, or Linux, and administrator rights. Chromebooks and iPads will not work.

Editors and IDEs

  • VS Code, with the Quarto, Python, R, and Jupyter extensions (and WSL on Windows)
  • Positron, Posit’s data-science IDE; install R and Python first so it can find them

Terminal applications

Mac users

  • Open the native Terminal app (Cmd-Space, type “Terminal”), or install another terminal like iTerm2
  • Install Apple’s command-line developer tools (compilers and Git): in Terminal, run xcode-select --install and click Install
  • Optional: Homebrew, a package manager for command-line software

Linux users

  • Open your distribution’s terminal app (often Ctrl-Alt-T)
  • Install the compiler toolchain: sudo apt install build-essential gfortran (Ubuntu/Debian)

Windows users

  • Guide: https://learn.microsoft.com/windows/wsl/install
  • Run Windows PowerShell as administrator
  • Install WSL2 and Ubuntu by typing wsl --install (this does both; if Ubuntu does not appear afterwards, wsl --install -d Ubuntu)
  • Restart your computer
  • If it fails: run Windows Update, enable virtualization in the BIOS/UEFI, then wsl --update and try again

Accessing the shell on Windows

  • Open Ubuntu from the Start menu and set up a username and password
  • These do not have to match your login info for Windows; nothing appears while you type the password, which is normal
  • Note that this is the Ubuntu Linux system you just installed, not Windows PowerShell
  • Run sudo apt update then sudo apt upgrade to ensure everything is up to date
  • Then install the compiler toolchain: sudo apt install build-essential gfortran
  • Keep your course folders and files inside your Ubuntu home directory (~); your Windows files are reachable from Ubuntu at /mnt/c/Users/<name>
  • Install R, Python, VS Code, and Positron as ordinary Windows programs, not inside Ubuntu

Scripting languages

R

  • Latest version of R (install here); on a Mac pick the installer matching your chip (Apple menu → About This Mac: arm64 for Apple silicon, x86_64 for Intel); on Windows choose “base”; on Ubuntu sudo apt install r-base r-base-dev
  • Windows only: Rtools matching your R version, so packages can be compiled
  • Once R is installed, in the R console: install.packages("tidyverse")

Python

  • Python 3 from python.org; on Windows, check “Add python.exe to PATH” on the first installer screen
  • Alternatives: uv or Miniconda/Miniforge; any one is fine, just pick one
  • On Ubuntu/WSL: sudo apt install python3-pip python3-venv

Quarto and LaTeX

  • Latest version of Quarto (install here)
  • Then, in a terminal: quarto install tinytex (a small LaTeX distribution; or tinytex::install_tinytex() from R)
  • A full LaTeX distribution (MacTeX, MiKTeX, or TeX Live) works too if you already have one
  • Check with quarto check

Git and GitHub

  • Latest version of Git (install here); on a Mac it comes with the Xcode command-line tools, on Ubuntu sudo apt install git
  • A GitHub account (sign up here) using your UO email so you qualify for the Student Developer Pack

Check that it all works

Open a terminal (or the terminal inside VS Code or Positron) and run:

echo $SHELL
R --version
python3 --version
quarto --version
quarto check
git --version

Each should print a version, not “command not found”. If one is missing, close and reopen the terminal first (it only sees programs installed before it started), then see the troubleshooting table in the book.
