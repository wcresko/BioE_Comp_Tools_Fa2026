Appendix E - Core R Commands Reference

Author

Bill Cresko

Overview

TipHow to use this appendix

This is a look-it-up reference, not a tutorial. If you have never written R before, work through Appendix D - R Primer: RStudio, Positron & the R Language (the companion to Lecture 07) first. This page is the one to keep open in a second tab while you work, when you need to remember exactly how to subset a data frame, read a TSV, or summarise by group. Commands are grouped by task, and every block ends with a short interpretation of the pieces that matter. For printable one-page versions, see the course Resources page and the Posit cheatsheets (https://posit.co/resources/cheatsheets/).

The examples use the native pipe |> and assume the tidyverse is installed (install.packages("tidyverse")). R itself is from the R Core Team (https://www.r-project.org).

The console & getting help

  • Commands
  • Interpretation
# Run a line: put the cursor on it and press Ctrl/Cmd + Enter
# (works in RStudio, Positron, and VS Code with the R extension)
2 + 2

# Help on a function: three related forms
?mean
help("mean")
example("mean")        # run the examples from the help page

# Fuzzy search when you don't know the exact name
??"linear model"
apropos("read")        # every visible object whose name contains "read"

# What is this thing?
class(x)               # high-level type: "numeric", "data.frame", "factor", "lm"
str(x)                 # structure: types, dims, first few values (your #1 tool)
summary(x)             # a quick numeric / factor summary
typeof(x)              # low-level storage type
length(x)              # number of elements
dim(x)                 # rows x cols (NULL for a plain vector)
names(x)               # element / column names

# Where am I, what's loaded?
getwd()                # current working directory
list.files()           # files in the working directory
ls()                   # objects in your workspace
sessionInfo()          # R version + every attached package version
  • str() is the single most useful inspection command: it tells you the type, the dimensions, and a preview all at once. Reach for it whenever an object surprises you.
  • ?fun opens the help page; ??term searches across installed packages when you only half-remember the name.
  • class() vs typeof(): class() is what you almost always want (it reports "data.frame", "factor", "lm"); typeof() exposes the underlying storage and is rarely needed.
  • sessionInfo() belongs at the bottom of every analysis report: it records which package versions produced your results.

Assignment & operators

  • Commands
  • Interpretation
# Assignment: `<-` is idiomatic R; `=` also works but reserve it for arguments
x <- 10
counts <- c(3, 0, 12, 5)

# Arithmetic
5 + 2; 5 - 2; 5 * 2; 5 / 2
5 %% 2        # modulo (remainder) -> 1
5 %/% 2       # integer division   -> 2
2 ^ 10        # exponent           -> 1024

# Comparison: return TRUE/FALSE (logical)
x == 10; x != 5; x > 3; x <= 10

# Logical operators
TRUE & FALSE        # element-wise AND
TRUE | FALSE        # element-wise OR
!TRUE               # NOT
a && b              # scalar AND (single value, short-circuits): used in `if`
xor(TRUE, FALSE)    # exclusive or

# Membership
3 %in% counts       # is 3 one of the elements? -> TRUE
  • Use <- for assignment and = for naming function arguments. Keeping them distinct makes code easier to read and is the community convention.
  • == tests equality and returns a logical; a single = would (accidentally) assign. This is one of the most common beginner bugs.
  • &/| work element-by-element over vectors; &&/|| require a single TRUE/FALSE and are what you use inside an if().
  • %in% is the readable way to ask “is this value in that set?” You will use it constantly to filter data (treatment %in% c("drugA", "drugB")).

Vectors: the fundamental R object

  • Creating & combining
  • Operations & summaries
  • Missing values
  • Interpretation
# c() combines values into a vector
genes  <- c("GAPDH", "ACTB", "COL1A1", "SOX9")
counts <- c(120, 88, 0, 305)

# Sequences
1:10                       # 1 2 3 ... 10
seq(0, 1, by = 0.25)       # 0.00 0.25 0.50 0.75 1.00
seq_len(4)                 # 1 2 3 4   (safe for length 0)
seq_along(genes)           # 1 2 3 4   (one index per element)
rep(c(0, 1), times = 3)    # 0 1 0 1 0 1
rep(c("A", "B"), each = 2) # "A" "A" "B" "B"

# Named vectors: a lightweight lookup table
named <- c(a = 1, b = 2, c = 3)
named["b"]                 # b: 2 (the name is kept)
# Vectorised math: applied element by element, no loop needed
counts * 2
log1p(counts)              # log(1 + x): a log transform that tolerates zeros,
                           # common for count data

# Summaries
sum(counts); mean(counts); median(counts)
min(counts); max(counts); range(counts)
sd(counts); var(counts)
length(counts)
quantile(counts, c(0.25, 0.5, 0.75))

# Order & rank
sort(counts)               # 0 88 120 305 (values, ascending)
sort(counts, decreasing = TRUE)
order(counts)              # 3 2 1 4: the indices that would sort it
which.max(counts)          # 4: index of the maximum
rev(counts)                # reverse
v <- c(1, 2, NA, 4)
is.na(v)                   # FALSE FALSE  TRUE FALSE
sum(v)                     # NA  (NA propagates!)
sum(v, na.rm = TRUE)       # 7   (drop NAs in the summary)
mean(v, na.rm = TRUE)      # 2.333333
v[!is.na(v)]               # 1 2 4: keep only the non-missing values
na.omit(v)                 # same values, plus an attribute recording what was dropped
  • Almost every operation in R is vectorised: counts * 2 multiplies every element at once. Writing explicit loops to do this is slower and harder to read; let the vector do the work.
  • seq_len() and seq_along() are safer than 1:n because 1:0 surprisingly gives c(1, 0); the seq_* helpers give an empty sequence for length-0 inputs.
  • NA is contagious: any summary touching an NA returns NA unless you pass na.rm = TRUE. Real data has missing values, so this argument appears everywhere.
  • order() returns positions, not values. It is how you sort by one column and carry the rest of the row along (df[order(df$x), ]).

Indexing & subsetting

  • Vectors
  • Conditional selection
  • Interpretation
x <- c(10, 20, 30, 40, 50)

x[1]              # 10           R is 1-indexed (NOT 0)
x[c(2, 4)]        # 20 40        multiple positions
x[-1]             # 20 30 40 50  drop the first
x[2:4]            # 20 30 40     a range
x[x > 25]         # 30 40 50     logical / conditional subset
x[c(TRUE, FALSE)] # 10 30 50     the mask is recycled
x <- c(5, 12, 0, 8, 25)

which(x > 10)              # 2 5    positions where the condition is TRUE
x[which(x > 10)]           # 12 25
any(x > 20)                # TRUE   is at least one TRUE?
all(x > 0)                 # FALSE  are they all TRUE?

# ifelse(): vectorised if/else, returns a vector the same length
ifelse(x > 10, "high", "low")
# "low" "high" "low" "low" "high"

# Recode with case_when() (dplyr): a multi-way ifelse
dplyr::case_when(
  x > 20 ~ "very high",
  x > 10 ~ "high",
  TRUE   ~ "low"          # the default / catch-all
)
# "low" "high" "low" "low" "very high"
  • R indexes from 1, and x[-1] means “everything except position 1” (negative indices drop elements; they do not count from the end as in Python).
  • Logical subsetting (x[x > 25]) is the most common pattern: build a TRUE/FALSE mask, then keep the TRUEs. The same idea filters the rows of a data frame.
  • which() converts a logical mask into integer positions; use it when you want the index rather than the value.
  • ifelse() is vectorised and element-wise (use it on columns); a plain if() takes a single condition and controls program flow. Mixing them up is a classic error.

Data frames & tibbles

  • Building & inspecting
  • Indexing df[row, col]
  • Interpretation
df <- data.frame(
  sample_id  = c("S1", "S2", "S3"),
  treatment  = c("control", "drug", "control"),
  cell_count = c(4210, 8800, 1500)
)

# A tibble: the tidyverse data frame (prints nicer, shows column types)
tb <- tibble::tibble(
  sample_id = c("S1", "S2", "S3"),
  treatment = c("control", "drug", "control")
)

head(df, 3)        # first rows
tail(df)           # last rows
nrow(df); ncol(df) # dimensions
colnames(df)       # column names
rownames(df)       # row names
dplyr::glimpse(df) # tidyverse str(): transposed, very readable
df[1, ]                  # first row, all columns
df[, "cell_count"]       # the cell_count column (as a vector)
df$cell_count            # same: $ is the everyday accessor
df[["cell_count"]]       # same: [[ ]] when the name is in a variable
df[1:2, c("sample_id", "treatment")]   # rows 1-2, two columns

# Conditional row subset (base R)
df[df$treatment == "control", ]        # rows where treatment is control
df[df$cell_count > 2000, "sample_id"]  # "S1" "S2"

# Add / modify a column
df$log_count <- log10(df$cell_count)
df$pass <- df$cell_count > 2000
  • A data frame is the rectangular table at the center of almost every analysis: columns can be different types (character, numeric, factor), but every column has the same length.
  • df[row, col] is the base-R two-index accessor; leaving a slot blank means “all of them” (df[, "x"] = all rows of column x).
  • $ is the quick way to grab one column by name; [[ ]] does the same but also accepts a name held in a variable (df[[var]]).
  • Tibbles (from tibble() or any tidyverse reader) print only the first 10 rows, show column types, and are stricter about partial name matching. They behave like data frames almost everywhere.

Reading & writing data

  • Read
  • Write
  • Interpretation
# Tidyverse readers (return tibbles, fast, sensible defaults): recommended
library(readr)
dat <- read_csv("measurements.csv")      # comma-separated
dat <- read_tsv("sample_sheet.tsv")      # tab-separated
dat <- read_delim("file.txt", delim = "|")

# Base R equivalents
dat <- read.csv("measurements.csv")
dat <- read.delim("sample_sheet.tsv")    # tab-separated by default
dat <- read.table("file.txt", header = TRUE, sep = "\t")

# Excel (readxl) and R's native binary format
dat <- readxl::read_excel("plate_reader.xlsx", sheet = 1)
obj <- readRDS("model_fit.rds")          # one R object, exactly as saved
write_csv(dat, "results.csv")            # readr: no row names, UTF-8
write_tsv(dat, "results.tsv")
write.csv(dat, "results.csv", row.names = FALSE)   # base R

saveRDS(obj, "model_fit.rds")            # save any single R object
save(a, b, file = "workspace.RData")     # save several named objects
  • Prefer the readr functions (read_csv, read_tsv): they are faster, report the column types they guessed, and return a tibble. The base-R read.csv/read.table family still works and is what you will see in older scripts.
  • .rds (saveRDS/readRDS) stores one object with its exact structure: a good way to checkpoint a cleaned data set or a fitted model between steps. .RData (save/load) stores several named objects and restores them under those same names.
  • When writing CSVs with base R, pass row.names = FALSE; otherwise you get a phantom first column of row numbers that confuses the next tool that reads the file.
  • Always check an import with glimpse() or str() immediately: a silently misparsed column (a number read as text) causes errors three steps later. See Appendix G for more on file formats.

Control flow

  • if / for / while
  • Interpretation
# if / else if / else
x <- 12
if (x > 10) {
  message("high")
} else if (x > 5) {
  message("medium")
} else {
  message("low")
}

# for loop over values
for (g in c("GAPDH", "ACTB", "SOX9")) {
  cat("checking", g, "\n")
}

# for loop over indices
for (i in seq_len(3)) {
  cat("iteration", i, "\n")
}

# while loop
n <- 1
while (n <= 3) {
  cat("n =", n, "\n")
  n <- n + 1
}

# break / next
for (i in 1:10) {
  if (i == 3) next     # skip this iteration
  if (i == 6) break    # stop the loop
  print(i)             # prints 1, 2, 4, 5
}
  • if () takes a single TRUE/FALSE; to choose element-by-element across a vector use ifelse() or case_when() instead (see the indexing section).
  • Iterate over the values directly (for (g in genes)) when you need each element, or over seq_len(n) / seq_along(x) when you need the index. Avoid 1:length(x), which misbehaves for empty inputs.
  • In R you rarely need an explicit loop for data transformation: vectorised operations and the apply / purrr::map family (next section) are usually clearer. Reserve loops for genuinely sequential work (e.g., a simulation where each step depends on the last).
  • next skips to the next iteration; break exits the loop entirely.

The apply / map family

  • Base R apply
  • Tidyverse purrr
  • Interpretation
m <- matrix(1:12, nrow = 3)

apply(m, 1, sum)        # apply over ROWS    (margin 1) -> 22 26 30
apply(m, 2, mean)       # apply over COLUMNS (margin 2) -> 2 5 8 11

# Over a list/vector -> a list
lapply(1:3, function(i) i^2)        # list(1, 4, 9)

# Over a list/vector -> simplified to a vector/matrix
sapply(1:3, function(i) i^2)        # 1 4 9
vapply(1:3, function(i) i^2, numeric(1))   # type-safe sapply

# Apply a function within groups
tapply(mtcars$mpg, mtcars$cyl, mean)       # mean mpg per cylinder count
library(purrr)

map(1:3, \(x) x^2)             # always returns a list
map_dbl(1:3, \(x) x^2)         # returns a double vector: 1 4 9
map_chr(letters[1:3], toupper) # "A" "B" "C"
map2_dbl(1:3, 4:6, \(x, y) x + y)   # iterate over two inputs: 5 7 9

# Read a folder of files into one table
files <- list.files("data", pattern = "\\.tsv$", full.names = TRUE)
all_data <- readr::read_tsv(files, id = "source")   # readr reads many files at once
# or, more generally:
all_data <- files |> map(readr::read_tsv) |> list_rbind(names_to = "source")
  • The apply family replaces loops with a single expression: “run this function over every row / column / element.” apply(m, 1, ...) works over rows, apply(m, 2, ...) over columns (remember: 1 = rows, 2 = columns).
  • sapply tries to simplify the result to a vector/matrix; lapply always returns a list. When you need a guaranteed type, vapply (base) or the typed map_* (purrr) protect you from a surprise list.
  • purrr’s map_* functions are the tidyverse version: the suffix names the output type (map_dbl -> double, map_chr -> character). \(x) x^2 is R’s short form of function(x) x^2 (R 4.1+); older code uses the purrr formula ~ .x^2.
  • read_tsv(files, id = "source") is the idiomatic one-liner for reading a folder of same-shaped files into a single tidy table, with a column recording which file each row came from.

Writing functions

  • Commands
  • Interpretation
# A function that computes the coefficient of variation
cv <- function(x, na.rm = TRUE) {
  sd(x, na.rm = na.rm) / mean(x, na.rm = na.rm)
}

cv(c(4, 9, 12, 5))           # call it
cv(x = c(4, 9, 12, 5))       # name the argument: order-independent

# Multiple arguments, with a default
passes_viability <- function(viability, min_viability = 0.8) {
  viability >= min_viability   # the last expression is the return value
}
passes_viability(c(0.95, 0.72, 0.88))                       # TRUE FALSE TRUE
passes_viability(c(0.95, 0.72, 0.88), min_viability = 0.9)  # TRUE FALSE FALSE

# Explicit return() for an early exit
safe_log <- function(x) {
  if (any(x < 0)) return(NA_real_)
  log1p(x)
}
  • A function is name <- function(args) { body }. The value of the last expression is returned automatically; return() is only needed for an early exit.
  • Give sensible defaults (min_viability = 0.8) so callers can omit common arguments. Defaults are used only if the caller does not supply the argument.
  • Call with named arguments for anything past the first one or two: rnorm(n = 100, mean = 37, sd = 0.5) is far clearer than rnorm(100, 37, 0.5), and it matters more as function signatures get longer.
  • Variables created inside a function are local: they do not leak into your workspace, which keeps analyses clean and reproducible.

Strings, factors & dates

  • Strings (stringr)
  • Factors (forcats)
  • Dates (lubridate)
  • Interpretation
library(stringr)

str_length("COL1A1")                           # 6
str_c("sample", 1:3, sep = "_")                # "sample_1" "sample_2" "sample_3"
str_sub("sample-01", 1, 6)                     # "sample"
str_detect(c("COL1A1", "ACTB", "COL2A1"), "^COL")   # TRUE FALSE TRUE (regex match)
str_replace("S01_rep1.fastq.gz", "\\.fastq\\.gz$", "")   # "S01_rep1"
str_split("a,b,c", ",")                        # list(c("a", "b", "c"))
toupper("sox9"); tolower("SOX9")               # "SOX9"  "sox9"
trimws("  spaced  ")                           # "spaced"
paste0("well_", c("A1", "A2", "A3"))           # base R: "well_A1" "well_A2" "well_A3"
f <- factor(c("control", "drug", "control"), levels = c("control", "drug"))
levels(f)                                 # "control" "drug" (control is the reference)
table(f)                                  # counts per level: control 2, drug 1

library(forcats)
fct_relevel(f, "drug")                    # make drug the first (reference) level
fct_infreq(f)                             # order levels by frequency
droplevels(f[f == "control"])             # drop unused levels after subsetting
Sys.Date()                                # today's date
as.Date("2026-09-22")                     # parse ISO-format text as a Date
as.Date("2026-10-01") - as.Date("2026-09-22")   # Time difference of 9 days

library(lubridate)
d <- ymd("2026-09-22")                    # also mdy(), dmy() for other orders
month(d); year(d); wday(d, label = TRUE)
  • stringr functions all start with str_ and take the string first and the pattern second: consistent and pipe-friendly. Patterns are regular expressions (see Appendix B), e.g. str_detect(genes, "^COL") for “starts with COL”. Note that a literal . must be written \\. in an R string.
  • str_replace(x, "\\.fastq\\.gz$", "") is the everyday trick for stripping a file extension to recover a sample name.
  • A factor is a categorical variable with a fixed set of ordered levels; the first level is the reference that linear models, ANOVA, and plots treat as the baseline. Use fct_relevel()/relevel() to set which group is the control.
  • After subsetting, unused factor levels linger and clutter tables and plots; droplevels() removes them.
  • Store dates in ISO YYYY-MM-DD format in your data files; R and every other tool read it unambiguously.

Data wrangling with dplyr

  • The core verbs
  • Interpretation
library(dplyr)

# samples: one row per sample, with sample_id, treatment, cell_count, viability
samples |>
  filter(viability > 0.8) |>                        # keep rows matching a condition
  mutate(live_cells = cell_count * viability) |>    # add / change columns
  select(sample_id, treatment, live_cells) |>       # keep / reorder columns
  arrange(desc(live_cells)) |>                      # sort rows
  slice_head(n = 5)                                 # first 5 rows

# Group-wise summaries: the heart of dplyr
samples |>
  group_by(treatment) |>
  summarise(
    n_samples      = n(),                           # rows per group
    mean_viability = mean(viability),
    sd_viability   = sd(viability),
    .groups        = "drop"
  )

# Counting and joining
count(samples, treatment)                           # quick frequency table
left_join(samples, treatment_info, by = "treatment")  # add columns from a second table
  • The pipe |> reads left-to-right: “take samples, then filter, then mutate…” Each verb takes a data frame and returns a data frame, so they chain cleanly. The older magrittr pipe %>% does the same thing and appears in lots of existing code.
  • The five verbs cover most work: filter() (rows by condition), select() (columns by name), mutate() (new/changed columns), arrange() (sort), summarise() (collapse to one row per group).
  • group_by() + summarise() is the split-apply-combine pattern (“mean viability per treatment”). Add .groups = "drop" to avoid a lingering grouping.
  • left_join() attaches information from a second table (e.g., drug names and doses in treatment_info) by a shared key column, keeping every row of the first.

Plotting with ggplot2

  • The grammar
  • Interpretation
library(ggplot2)

# One point per sample, colored by treatment
ggplot(samples, aes(x = cell_count, y = viability, colour = treatment)) +
  geom_point(size = 3, alpha = 0.8) +
  scale_x_log10() +
  labs(x = "Cell count", y = "Viability", colour = "Treatment") +
  theme_minimal()

# Distribution per group + faceting (penguins from the palmerpenguins package)
library(palmerpenguins)
ggplot(penguins, aes(x = species, y = body_mass_g, fill = species)) +
  geom_boxplot() +
  facet_wrap(~ island) +
  theme(legend.position = "none")

# Save the last (or a named) plot
ggsave("viability_scatter.png", width = 6, height = 4, dpi = 300)
  • A ggplot is built in layers joined by +: ggplot(data, aes(...)) sets the data and the aesthetic mapping (which column drives x, y, colour), then each geom_* draws a layer.
  • Map a variable inside aes() (colour = treatment) to let it vary with the data; set a constant outside aes() (size = 3) to fix it for every point. Confusing the two is the most common ggplot mistake.
  • facet_wrap(~ var) splits one plot into a small-multiple grid, one panel per group: the standard way to compare conditions side by side.
  • scale_* transforms or relabels an axis/legend (e.g., scale_x_log10() for skewed measurements such as counts or concentrations), and ggsave() writes the figure at a publication-quality resolution.

Packages & the environment

  • Commands
  • Interpretation
# Install once (per machine), from CRAN
install.packages("tidyverse")

# Bioconductor packages (biology-specific: genomics, sequencing, imaging ...)
if (!requireNamespace("BiocManager", quietly = TRUE))
  install.packages("BiocManager")
BiocManager::install("Biostrings")

# Load every session
library(tidyverse)

# Use one function without attaching the whole package
dplyr::filter(samples, treatment == "drug")

# What version am I running?
packageVersion("dplyr")
R.version.string
sessionInfo()
  • install.packages() downloads a package once onto the machine; library() loads it into every R session where you use it. New users often try to library() something they never installed; that is the “there is no package called …” error.
  • Many biology-specific packages live on Bioconductor, not CRAN: install them with BiocManager::install("name").
  • pkg::function() calls one function without attaching the whole package. It documents exactly where a function comes from and avoids name clashes (e.g., dplyr::filter vs stats::filter).
  • End scripts with sessionInfo() so the exact package versions are recorded with the results. For fully reproducible environments across machines (your laptop, a collaborator’s, Talapas), use renv, which records each project’s package versions in a lockfile (renv.lock) that others can restore with renv::restore(): https://rstudio.github.io/renv/.

Common gotchas

WarningThings that bite everyone
  • 1-indexing. R counts from 1, and x[-1] drops the first element (it does not mean “the last” as in Python).
  • = vs ==. = assigns/names an argument; == tests equality. Using = where you meant == is a logic bug (inside if() R will at least throw an error).
  • NA propagates. mean(c(1, NA, 3)) is NA; add na.rm = TRUE to ignore missing values.
  • Strings to factors. In R versions before 4.0, data.frame() and read.csv() converted text to factors by default; modern R and tibbles do not. If a character column behaves oddly (especially in old code), check its class().
  • Floating-point equality. 0.1 + 0.2 == 0.3 is FALSE; compare decimals with all.equal() or a tolerance, never ==.
  • & vs &&. Use &/| on vectors (element-wise filtering) and &&/|| on single values inside if().
  • Recycling. Operating on vectors of different lengths silently recycles the shorter one; a warning appears only if the longer length is not a multiple of the shorter. Check length() when results look wrong.
  • Working directory. “cannot open file … No such file or directory” almost always means the path is relative to a different folder than you think. Check getwd() and use an RStudio Project or open the project folder in Positron/VS Code.
