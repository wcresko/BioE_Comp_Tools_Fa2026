Appendix F - Quarto & Markdown Syntax

Author

Bill Cresko

Overview

TipHow this appendix fits the course

This appendix is a reference for the Markdown introduced in Lecture 00 (bootcamp) and the Quarto, LaTeX math, and publishing material in Lecture 08. Every page of this course website is a Quarto (.qmd) file: plain-text Markdown with executable code chunks, rendered to HTML and published with GitHub Pages. This is a look-it-up reference for the syntax: headings and emphasis, code chunks and their options, figures and tables, callouts and tabsets, math and citations. If you have written R Markdown before, Quarto will feel familiar; it is the modern successor.

For the canonical, always-current documentation, see the Quarto guide. Printable cheat sheets are linked from the Resources hub, and unfamiliar terms are defined in the Glossary.

Anatomy of a .qmd file

A Quarto document has three kinds of content: a YAML header, Markdown prose, and code chunks.

---
title: "My Analysis"
author: "Your Name"
format: html
---

## A section heading

Ordinary prose written in **Markdown**.

```{r}
# An executable code chunk
summary(cars)
```

More prose, and an *inline* result: `r nrow(cars)` rows.
  • The pieces
  • Interpretation
  • The block between the --- fences at the very top is the YAML header (front matter): document-level settings such as title, author, output format, and options.
  • Everything else is Markdown prose, with the formatting shown in the sections below.
  • Triple-backtick blocks tagged with a language in braces (```{r}, ```{python}) are executable code chunks: Quarto runs them and inserts the results when it renders.
  • `r ...` embeds an inline R result in a sentence, so numbers in your text update automatically when the data change.
  • YAML is indentation-sensitive (two spaces, never tabs), and the --- fences must be the first thing in the file. A stray tab or a missing fence is the most common cause of “my document won’t render.”
  • The file extension is .qmd. Rendering turns it into HTML (like this site), PDF, Word, slides, or a dashboard: the same source, many outputs.
  • A ```bash block without braces is just displayed, not run. Braces (```{r}) are what make a chunk executable.

The YAML header

  • Common keys
  • Interpretation
---
title: "Hydrogel Stiffness Report"
subtitle: "PEG hydrogels, three crosslinker concentrations"
author: "Your Name"
date: "2026-10-15"
format:
  html:
    toc: true              # table of contents
    toc-depth: 3           # include H1-H3 in the TOC
    toc-location: left
    code-fold: true        # collapse code behind a toggle
    code-tools: true       # add a "show all code" menu
    number-sections: true
    embed-resources: true  # one self-contained .html file
    theme: cosmo
execute:
  echo: true               # show the code
  warning: false           # hide warnings
  message: false           # hide messages
bibliography: references.bib
csl: nature.csl
---
  • format: chooses the output. html, pdf, docx, revealjs (slides), and gfm (GitHub-flavored Markdown) are the common ones; nested keys under it (toc, theme, …) configure that format.
  • execute: sets defaults for every code chunk, e.g., echo: false to hide all code in a report, or warning: false to suppress noise. Individual chunks can override these.
  • embed-resources: true bundles images, CSS, and JavaScript into a single .html file you can email or upload anywhere. Websites usually leave it off, because the site’s shared files are published alongside the pages.
  • bibliography: and csl: wire up citations (see the citations section). Indentation matters: two spaces per level.
  • In a website, settings shared by every page go in _quarto.yml instead of being repeated in each file.

Markdown basics

  • Source
  • Interpretation
# Heading level 1 (usually the page title; one per document)
## Heading level 2
### Heading level 3

Plain paragraph. Separate paragraphs with a **blank line**;
a single line break does *not* start a new paragraph.

*italic*  or  _italic_
**bold**  or  __bold__
***bold italic***
~~strikethrough~~
`inline code`  (monospace, e.g. a file name like `stiffness.csv`)
H~2~O  and  E = mc^2^   (subscript / superscript)

> A blockquote: pulled-out text,
> often a definition or a caution.

Three or more dashes on their own line make a horizontal rule:

---
  • Headings are # symbols; the number of # sets the level (1 to 6). Each heading becomes an entry in the table of contents and a linkable anchor. Put a space after the #.
  • Blank lines matter. A new paragraph requires a blank line between blocks; a single newline is treated as a continuation of the same paragraph.
  • Wrap code, commands, file names, and variable names in single backticks (`stiffness.csv`) so they render in monospace and stand out from prose.
  • Emphasis: one marker = italic, two = bold. ~sub~ and ^super^ give H2O and x2.

Lists

  • Source
  • Interpretation
Unordered list:

-   First item
-   Second item
    -   Nested item (indent four spaces)
    -   Another nested item
-   Third item

Ordered list:

1.  Prepare the hydrogels
2.  Measure stiffness
3.  Analyze the data
    a.  sub-step
    b.  sub-step

Task list:

-   [x] Done
-   [ ] Not done yet

Definition list:

Young's modulus
:   A material's stiffness: the ratio of stress to strain.
  • Use - (or *) for bullets and 1. for numbers. Quarto renumbers ordered lists automatically, so you can write 1. on every line and still get 1, 2, 3.
  • Nesting requires indentation: four spaces under the parent item. Under-indenting is the usual reason a sub-list renders flat.
  • Leave a blank line before a list starts, or it may be glued onto the preceding paragraph.
  • Definition lists (Term, then : definition on the next line) are a natural fit for glossaries like the course Glossary.

# Images
![Hydrogel stiffness vs. crosslinker concentration](images/stiffness.png)

# Image with a caption, size, and alt text (figure attributes)
![Stiffness increases with crosslinker](images/stiffness.png){#fig-stiffness width=80%
  fig-alt="Scatter plot: Young's modulus rises from about 2 to 20 kPa as crosslinker increases"}
  • Link syntax is [visible text](target). The target can be an external URL, another page in the same Quarto project, or a #heading-anchor on the current page. Within a project you can link to the .qmd file and Quarto converts the link to the rendered .html page.
  • Heading anchors are the heading text, lowercased, with spaces turned into hyphens (## Markdown basics becomes #markdown-basics).
  • Images use the same syntax with a leading !. The text in brackets becomes the caption. Always describe the image for readers using screen readers, with fig-alt= when the caption alone is not enough.
  • The {...} after an image sets attributes: #fig-stiffness gives it a cross-reference label, width=80% sizes it, and fig-alt= sets the screen-reader description.
  • Image paths are relative to the .qmd file. A broken path renders as a missing image, so check spelling and capitalization (Linux and GitHub Pages are case-sensitive).

Code chunks

Code chunks are what make Quarto more than a Markdown previewer: chunks of R (or Python, Bash, …) are executed when the document renders.

  • A chunk & its options
  • Common options
  • Interpretation
```{r}
#| label: fig-stiffness
#| echo: true
#| warning: false
#| fig-cap: "Young's modulus of PEG hydrogels by crosslinker concentration."
#| fig-width: 6
#| fig-height: 4

library(ggplot2)
ggplot(gels, aes(x = crosslinker_pct, y = modulus_kPa)) +
  geom_point() +
  geom_smooth(method = "lm")
```
Option Effect
echo: false Run the code but hide it; show only the output
eval: false Show the code but do not run it
include: false Run it but show neither code nor output (setup chunks)
output: false Show the code, hide its output
warning: false / message: false Suppress warnings / messages
fig-cap: / tbl-cap: Caption a figure / table
fig-width: / fig-height: Figure size in inches
cache: true Cache results so slow chunks don’t re-run
label: Name the chunk (also its cross-reference id)
  • Chunk options use the hash-pipe #| comment syntax at the top of the chunk, one option per line, written as YAML (option: value). This is the Quarto style; older R Markdown put options inside the {r, ...} header.
  • The options you will use constantly: echo (show the code?), eval (run the code?), include (show anything?), and warning/message (silence noise). A hidden setup chunk at the top that loads packages is typically #| include: false.
  • label: names a chunk so you can cross-reference its figure (@fig-...), and so error messages tell you which chunk failed.
  • Set document-wide defaults in the YAML execute: block and override them per chunk only where needed. (The appendices on this site set eval: false, so their code is displayed but not run.)

Figures, tables & cross-references

  • Source
  • Interpretation
A Markdown table (pipes and dashes; colons set alignment):

| Crosslinker (%) | Replicates | Mean modulus (kPa) |
|:----------------|:----------:|-------------------:|
| 2.5             |     4      |                3.1 |
| 5.0             |     4      |                8.7 |
| 10.0            |     4      |               19.4 |

: Hydrogel stiffness by crosslinker concentration {#tbl-stiffness}

Cross-references refer to a labelled figure, table, or section:

As @fig-counts shows, cell counts rise over the first three days.
Mean stiffness values are listed in @tbl-stiffness.
See @sec-code-chunks for the chunk options.

A code chunk that produces a referenceable figure:

```{r}
#| label: fig-counts
#| fig-cap: "Cell counts over time."
plot(1:5, c(1.0, 1.9, 4.1, 8.3, 15.8) * 1e4,
     xlab = "Day", ylab = "Cells per well")
```
  • Tables are pipes (|) plus a --- separator row; colons in the separator set alignment (:--- left, :--: centre, ---: right). Add a caption and id with a : caption {#tbl-id} line underneath.
  • Cross-references turn a label into an auto-numbered, hyperlinked “Figure 3” or “Table 1”. The label prefix matters: fig- for figures, tbl- for tables, sec- for sections, eq- for equations. Reference it with @fig-counts.
  • A section becomes referenceable when you give its heading an id, e.g. ## Code chunks {#sec-code-chunks}. Section references also require number-sections: true in the YAML.
  • A code chunk becomes a referenceable figure when its label: starts with fig- and it has a fig-cap:. Quarto handles the numbering, so inserting a new figure renumbers everything automatically.
  • For larger tables generated in R, use knitr::kable() or the gt package inside a chunk rather than typing Markdown by hand.

Callout blocks

The colored boxes throughout these appendices are Quarto callouts.

  • Source
  • Rendered
  • Interpretation
::: {.callout-note}
General information worth flagging.
:::

::: {.callout-tip title="Pro tip"}
A suggestion or shortcut, with a custom title.
:::

::: {.callout-warning}
Something that commonly trips people up.
:::

::: {.callout-important}
Don't-skip-this material.
:::

::: {.callout-caution collapse="true"}
A collapsible box: it starts folded; click to open.
:::
Note

General information worth flagging.

TipPro tip

A suggestion or shortcut, with a custom title.

Warning

Something that commonly trips people up.

  • A callout is a fenced div: three or more colons, then {.callout-TYPE}, your content, then a closing :::. The five types (note, tip, warning, important, caution) each get a distinct color and icon.
  • Add title="..." for a custom heading and collapse="true" to make it start folded (handy for optional detail or exercise answers).
  • The opening and closing fences must each be on their own line with a blank line around the block. Otherwise the div doesn’t close, and the rest of the page renders inside the box.

Tabsets & layout

  • Source
  • Interpretation
# Tabset: the tabbed panels used all over these appendices
::: panel-tabset
## R
```{r}
mean(1:10)
```

## Python
```{python}
sum(range(1, 11)) / 10
```
:::

# Multi-column layout
::: {layout-ncol=2}
![Before treatment](images/before.png)

![After treatment](images/after.png)
:::
  • A tabset is a fenced div marked ::: panel-tabset; each heading one level below the surrounding section inside it becomes a tab. These appendices use tabsets to put “Source” and “Interpretation” side by side without doubling the page length.
  • Generic fenced divs ::: {.class} are the all-purpose layout tool: {layout-ncol=2} arranges its children in two columns, {.column-margin} pushes content into the margin, and any CSS class in your stylesheet can be targeted this way.
  • Nesting works, but the outer div needs more colons than the one inside it (:::: around :::) so it is clear which fence closes which block.

Math, citations & footnotes

  • Math (LaTeX)
  • Citations & footnotes
  • Interpretation
Inline math: the sample mean is $\bar{x}$ and the variance is $s^2$.

Display math (centred, on its own line):

$$
\bar{x} = \frac{1}{n}\sum_{i=1}^{n} x_i
\qquad
s^2 = \frac{1}{n-1}\sum_{i=1}^{n} \left(x_i - \bar{x}\right)^2
$$

A labelled, referenceable equation:

$$
E = \frac{\sigma}{\varepsilon}
$$ {#eq-modulus}

As @eq-modulus states, Young's modulus is stress divided by strain.
Data should be findable, accessible, interoperable, and reusable [@wilkinson2016].
Tidy data make analysis easier [@wickham2014; @broman2018].
As @wickham2014 argued, ... (in-text: the author becomes part of the sentence).

A footnote inline^[Like this one, defined right here.]

Or a referenced footnote.[^longnote]

[^longnote]: The note's text, defined anywhere in the document.
  • Math is LaTeX between dollar signs: $...$ inline and $$...$$ for a centred display block. Add {#eq-label} after a display equation to cross-reference it with @eq-label. Common symbols: Greek letters (\alpha, \sigma, \mu), fractions (\frac{a}{b}), sums (\sum_{i=1}^{n}), subscripts (x_i), and superscripts (x^2).
  • Citations use [@key], where key matches an entry in the BibTeX file (e.g., references.bib) named by the YAML bibliography: key. Separate multiple keys with ;. Quarto formats them and builds the reference list in the style set by csl:.
  • @key without brackets puts the author into the sentence (“As Wickham (2014) argued…”); [@key] puts the whole citation in parentheses (or a superscript number, depending on the style).
  • By default the reference list appears at the end of the document. To place it elsewhere, add a ::: {#refs} div followed by a closing ::: where you want it.
  • Reference managers such as Zotero (with the Better BibTeX plugin) can export a .bib file for you, and the visual editor in RStudio and Positron can insert citations by DOI.
  • Footnotes: inline with ^[...], or referenced with [^name] plus a [^name]: ... definition elsewhere.

Rendering

  • Commands
  • In your editor
  • Interpretation
# Render a single document to its default format
quarto render report.qmd

# Render to a specific format
quarto render report.qmd --to pdf
quarto render report.qmd --to docx

# Render the whole project / website (uses _quarto.yml)
quarto render

# Live preview: re-renders in the browser every time you save
quarto preview report.qmd

# Preview a whole website project
quarto preview

# Check your Quarto installation (R, Python, LaTeX)
quarto check
  • VS Code: install the Quarto extension. Open a .qmd file and click the Preview button in the editor toolbar (or press Ctrl+Shift+K / Cmd+Shift+K). A live preview opens and updates on each save.
  • Positron: Quarto support is built in. Use the same Preview button or keyboard shortcut.
  • RStudio: click Render (or press Ctrl+Shift+K / Cmd+Shift+K).
  • In every editor, the button runs quarto preview or quarto render for you, and you can always run those commands yourself in the terminal.
  • quarto preview opens a live-reloading browser tab. It is the fastest way to write, because you see changes as soon as you save.
  • quarto render with no file name renders the whole project according to _quarto.yml (for this course website, every page into docs/, which GitHub Pages then serves; see Appendix C). A single file name renders just that document.
  • --to FORMAT overrides the YAML to produce a one-off PDF or Word version from the same source. PDF output needs a LaTeX installation (quarto install tinytex provides a small one).
  • Documents with {r} chunks need R and the knitr and rmarkdown packages; {python} chunks need Python and Jupyter. quarto check reports what Quarto can find.
