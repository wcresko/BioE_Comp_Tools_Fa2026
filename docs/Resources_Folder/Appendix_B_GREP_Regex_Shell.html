Appendix B - GREP, Regular Expressions & Shell Scripting

Author

Bill Cresko

Overview

TipHow this appendix fits the course

This appendix is a look-it-up reference for Lecture 05 (GREP & regular expressions) and Lecture 06 (shell scripting). It covers three essential Unix skills: (1) using grep and regular expressions for pattern matching in text files, (2) quick one-line text editing and column processing with sed and awk, and (3) writing shell scripts to automate repetitive tasks. These are the tools you will use constantly when working with large data files on your laptop or on Talapas.

If you need a refresher on navigating the file system, pipes, and redirection first, see Appendix A - Computer Systems & the Command Line. Unfamiliar terms are defined in the Glossary. For the regular-expression engine in depth (greedy vs. lazy matching, backreferences, lookarounds), the classic reference is Jeffrey Friedl, Mastering Regular Expressions, 3rd ed. (O’Reilly, 2006), https://www.oreilly.com/library/view/mastering-regular-expressions/0596528124/.

GREP and Regular Expressions

What is GREP?

  • grep = Global Regular Expression Print
  • A fast text-search tool available on every Unix-like system (macOS, Linux, WSL, Talapas)
  • Searches for patterns in files or in input streams (pipes)
  • Prints the lines that match the pattern
  • Works line by line, so it handles files far too large to open in a text editor

Basic syntax:

grep [options] pattern [file...]
Note

Put the pattern in quotes ("..." or '...'). Without quotes, the shell may interpret characters such as *, ?, $, or | before grep ever sees them. Single quotes are the safest choice because the shell leaves everything inside them alone.

Basic GREP Usage

  • Common Options
  • Interpretation
# Search for a simple pattern
grep "ACGT" sequences.txt

# Case-insensitive search
grep -i "gene" annotations.txt

# Count matching lines (here: FASTA header lines)
grep -c "^>" proteins.fasta

# Show line numbers
grep -n "ERROR" logfile.txt

# Invert match (show non-matching lines)
grep -v "^#" data.txt    # Skip comment lines

# Search multiple files
grep "mutation" *.txt

# Search every file in a directory tree
grep -r "TODO" scripts/

# Print only the matching part of each line, not the whole line
grep -o "gene=[A-Za-z0-9]*" annotation.gff

# Quiet mode: print nothing, just set the exit status (useful in scripts)
grep -q "ERROR" logfile.txt && echo "Found an error"
  • -i ignores case — useful when you are unsure of capitalization
  • -c returns just the number of matching lines, not the lines themselves
  • -n shows line numbers — helpful for locating matches in large files
  • -v inverts the match — essential for filtering out headers or comments
  • -r searches recursively through directories
  • -o prints only the matched text, one match per line (pair it with wc -l to count individual matches rather than lines)
  • -q is silent; its exit status (0 = found, 1 = not found) is what matters
  • Searching multiple files with wildcards (*.txt) saves time

Introduction to Regular Expressions

  • Metacharacters
  • Examples
  • Interpretation

Regular expressions (regex) are patterns for matching text:

  • . = any single character
  • * = zero or more of the preceding character
  • + = one or more of the preceding character (extended regex)
  • ? = zero or one of the preceding character (extended regex)
  • ^ = start of line
  • $ = end of line
  • [abc] = any one character in the set
  • [^abc] = any one character NOT in the set
  • [a-z], [0-9] = character ranges
  • \ = escape a special character (e.g., \. matches a literal period)
Warning

Plain grep uses basic regular expressions (BRE), where +, ?, |, { }, and ( ) are treated as literal characters unless you backslash them (\+, \{3\}, …). With grep -E (extended regex, ERE) they are special without backslashes. When in doubt, use grep -E.

# Anchors
grep "^ATG" genes.txt         # Lines starting with ATG
grep "TAG$" genes.txt         # Lines ending with TAG
grep "A.G" sequences.txt      # A, any one character, then G

# Character classes
grep "[ACGT]" dna.txt         # Lines containing at least one DNA base
grep "[^ACGT]" dna.txt        # Lines containing at least one non-ACGT character
grep "[0-9]" data.txt         # Lines containing any digit

# Quantifiers (basic regex needs backslashes around the braces)
grep "A\{3\}" sequence.txt    # Lines containing AAA (a run of at least 3 A's)
grep "T\{2,4\}" sequence.txt  # Lines containing TT, TTT, or TTTT
grep "GC*" sequence.txt       # G followed by zero or more C's
  • grep reports a line if the pattern matches anywhere in it. A\{3\} therefore also matches a line containing AAAAAA, because AAA is inside it. Use anchors (^...$) to force the pattern to match the whole line.
  • [^ACGT] is a handy quality check: any line it prints contains something other than an uppercase DNA base (lowercase letters, N, spaces, or stray Windows carriage returns).
  • GC* matches every line that contains a G, because “zero C’s” is allowed. * is often more permissive than you expect.

Extended Regular Expressions

  • Syntax
  • Combining with Pipes
  • Useful POSIX Character Classes

Use grep -E for extended regex (egrep is an older, now-deprecated alias):

# Alternation (OR)
grep -E "start|stop|pause" commands.txt

# Grouping
grep -E "(ATG|GTG|TTG)" codons.txt

# Plus quantifier (one or more)
grep -E "A+T+G+" sequences.txt

# Question mark (optional character)
grep -E "colou?r" british_american.txt

# Braces without backslashes
grep -E "[ACGT]{20,}" primers.txt          # A run of 20 or more bases

# UniProt headers such as >sp|P69905|HBA_HUMAN ...
# In -E mode a bare | means OR, so escape it (\|) to match a literal pipe
grep -E "^>sp\|[A-Z0-9]+\|" uniprot.fasta
# Count unique sequence headers
grep "^>" sequences.fasta | sort | uniq | wc -l

# Extract gene names from the 9th (attributes) column of a GFF file
grep -v "^#" annotation.gff | cut -f9 | grep -oE "gene=[^;]+"

# Keep only lines with none of the three stop codons
grep -v -E "(TAA|TAG|TGA)" orfs.txt

# Search, then replace with sed (see the sed section below)
grep "gene" data.txt | sed 's/gene/GENE/g'
Class Matches
[[:digit:]] Digits, same as [0-9]
[[:alpha:]] Letters
[[:alnum:]] Letters and digits
[[:space:]] Spaces, tabs, and other whitespace
[[:upper:]] Uppercase letters
[[:lower:]] Lowercase letters

Note the double brackets: the outer [ ] is the character set, and [:digit:] is the class inside it.

Analyzing Sequence Content with GREP

The examples below use a small bacterial genome in FASTA format (ecoli.fa, about 5 MB). The same commands work on a human genome, but joining a 3 GB genome into a single line with tr -d '\n' needs a lot of memory. Save that for Talapas.

  • Base Counting
  • Pattern Finding
  • Interpretation
# Count total bases (drop headers, remove newlines, count characters)
grep -v "^>" ecoli.fa | tr -d '\n' | wc -c

# Count each type of base
grep -v "^>" ecoli.fa | tr -d '\n' | fold -w1 | sort | uniq -c

# Count G + C bases (divide by the total above to get GC content)
grep -v "^>" ecoli.fa | tr -d '\n' | tr -cd 'GCgc' | wc -c
# Count EcoRI restriction sites (GAATTC)
grep -v "^>" ecoli.fa | \
  tr -d '\n' | \
  grep -o "GAATTC" | \
  wc -l

# Find simple sequence repeats (e.g., ATATATATAT...)
# Note: searching line by line misses repeats that span a line break
grep -v "^>" ecoli.fa | grep -oE "(AT){5,}"

# Positions of the first 20 ATG start codons
# (-b gives a 0-based byte offset into the joined sequence)
grep -v "^>" ecoli.fa | \
  tr -d '\n' | \
  grep -b -o "ATG" | \
  head -20
  • grep -v "^>" removes header lines, leaving only sequence.
  • tr -d '\n' joins the sequence lines into one long line, so patterns that cross line breaks can be found.
  • tr -cd 'GCgc' deletes (-d) everything except (-c, complement) G and C, so wc -c counts only those bases.
  • Many reference genomes use lowercase letters for repeat-masked regions. Add -i to grep, or convert case first with tr 'acgt' 'ACGT', if you want to count both.
  • grep -o finds non-overlapping matches only, so it undercounts patterns that can overlap themselves (e.g., ATA in ATATA).

Stream Editing with sed and awk

grep finds lines. Two other classic Unix tools change or compute on lines as they stream past: sed (stream editor) and awk (a small column-oriented programming language). A handful of one-liners covers most everyday needs.

sed basics

  • One-liners
  • Editing in place
  • Interpretation
# Substitute the first "chr" on each line with "Chr"
sed 's/chr/Chr/' data.txt

# Substitute EVERY occurrence on each line (g = global)
sed 's/chr/Chr/g' data.txt

# Case-insensitive substitution (GNU sed)
sed 's/gene/GENE/gI' data.txt

# Use a different delimiter when the pattern contains slashes
sed 's|/old/path|/new/path|g' config.txt

# Delete lines that match a pattern (here: comment lines)
sed '/^#/d' data.txt

# Delete blank lines
sed '/^$/d' data.txt

# Delete the first line (e.g., a header)
sed '1d' data.csv

# Print only lines 10 through 20
sed -n '10,20p' data.txt

# Strip Windows carriage returns
sed 's/\r$//' windows_file.txt > unix_file.txt
# Linux / WSL / Talapas (GNU sed): edit the file directly
sed -i 's/old/new/g' file.txt

# macOS (BSD sed) requires an argument after -i ('' = no backup)
sed -i '' 's/old/new/g' file.txt

# Portable and safe: write to a new file, check it, then rename
sed 's/old/new/g' file.txt > file_fixed.txt
  • The substitution command is s/pattern/replacement/flags. The pattern is a regular expression (basic regex by default; use sed -E for extended).
  • Without g, only the first match on each line is replaced.
  • /pattern/d deletes matching lines; Nd deletes line number N.
  • sed prints to the screen and leaves the original file untouched unless you use -i. -i overwrites the file with no undo, so test the command without -i first.

awk basics

  • One-liners
  • Interpretation
# Print the first column (awk splits on whitespace by default)
awk '{print $1}' data.txt

# Print columns 1 and 3, separated by a tab
awk '{print $1 "\t" $3}' data.txt

# Print the whole line ($0) and the number of fields (NF)
awk '{print NF, $0}' data.txt

# Filter rows: keep lines where column 3 is greater than 100
awk '$3 > 100' data.txt

# Filter on a text value: keep rows where column 1 is exactly "chr1"
awk '$1 == "chr1"' data.txt

# Sum a column and print the total at the end
awk '{sum += $2} END {print sum}' data.txt

# Average of a column (NR = number of records/lines read)
awk '{sum += $2} END {print sum / NR}' data.txt

# CSV files: set the field separator with -F
awk -F',' '{print $2}' measurements.csv

# CSV: skip the header row (NR > 1), keep rows where column 4 > 5.0
awk -F',' 'NR > 1 && $4 > 5.0' measurements.csv

# Tab-separated output from CSV input
awk -F',' 'BEGIN {OFS="\t"} {print $1, $2}' measurements.csv
  • An awk program is pattern { action }. If the pattern is true for a line, the action runs. A pattern with no action prints the line; an action with no pattern runs on every line.
  • Fields are $1, $2, …; $0 is the whole line; NF is the number of fields on the line; NR is the current line number.
  • BEGIN { } runs before any input is read and END { } runs after the last line, which makes END the place to print totals.
  • -F',' sets the input field separator for CSV files; -F'\t' sets it to tab. The simple -F',' approach breaks on quoted CSV fields that contain commas. For those, use R (readr::read_csv(); see Appendix E) or Python.
  • Unlike bash, awk does decimal (floating-point) arithmetic, so it is a good way to compute percentages in a pipeline.

Shell Scripting

What is a Shell Script?

  • A plain-text file containing Unix commands
  • Automates repetitive tasks
  • Makes complex workflows reproducible
  • The foundation of analysis pipelines and of SLURM job scripts on Talapas
  • Can include:
    • Variables and arrays
    • Conditionals (if/then/else)
    • Loops (for/while)
    • Functions
    • Command-line arguments

Creating Your First Script

  • Code
  • How to Run
  • Interpretation
#!/bin/bash
# The first line is the "shebang": it tells the system which interpreter to use

# This is a comment - it documents your code
echo "Hello, Bioengineering!"

# Set a variable
NAME="DNA Analysis"
echo "Running $NAME"

# Use command output as a variable
DATE=$(date +%Y-%m-%d)
echo "Analysis date: $DATE"

# Simple (integer) calculation
COUNT=5
DOUBLE=$((COUNT * 2))
echo "Double of $COUNT is $DOUBLE"
# Save as first_script.sh, then:

# Option 1: Run with bash
bash first_script.sh

# Option 2: Make it executable once, then run it directly
chmod +x first_script.sh
./first_script.sh
  • The #!/bin/bash shebang tells the system which interpreter to use (#!/usr/bin/env bash is a more portable alternative)
  • Comments start with # and document your code
  • Variables are assigned with = and no spaces around it (NAME = "x" is an error)
  • $( ) captures a command’s output
  • $(( )) performs integer arithmetic only ($((7 / 2)) is 3); use awk or bc for decimals
  • The ./ in ./first_script.sh is needed because the current directory is not on your PATH

Command-Line Arguments

  • Code
  • Usage
  • Interpretation
#!/bin/bash
# Script: process_fasta.sh

echo "Script name: $0"       # $0 is the script name
echo "Number of arguments: $#"

# Check that enough arguments were provided
if [ $# -lt 2 ]; then
    echo "Usage: $0 input.fasta output.txt" >&2
    exit 1
fi

echo "Processing file: $1"   # First argument
echo "Output will be: $2"    # Second argument
echo "All arguments: $@"     # All arguments
# Run as:
./process_fasta.sh input.fa results.txt
  • $0 = script name, $1 = first argument, $2 = second, and so on
  • $# = total number of arguments
  • "$@" = all arguments as a list (keep the quotes when passing them on to another command so arguments containing spaces stay intact)
  • Always validate arguments before using them, and send error messages to standard error with >&2

Variables and Arrays

  • Code
  • Interpretation
#!/bin/bash

# Variables (no spaces around =)
SPECIES="Homo sapiens"
CHROMOSOME=21
GENE_COUNT=234

# Arrays
BASES=(A C G T)
echo "First base: ${BASES[0]}"
echo "All bases: ${BASES[@]}"

# Add to an array
BASES+=(N)

# Array length
echo "Number of bases: ${#BASES[@]}"

# String operations on file names
FILE="sample_001.fastq.gz"
NAME="${FILE%.fastq.gz}"     # Remove a suffix -> sample_001
echo "Sample name: $NAME"
  • Variables: no spaces around =; reference them with $VAR or ${VAR}
  • Quote variables when you use them ("$FILE") so values containing spaces do not get split into several words
  • Arrays are created with ( ) and indexed from 0 with ${arr[i]}
  • ${#arr[@]} gives the array length
  • ${var%pattern} removes a matching suffix; ${var#pattern} removes a matching prefix

Conditionals (if/then/else)

  • Code
  • Operators
  • Interpretation
#!/bin/bash

# Numeric comparisons
COUNT=100
if [ "$COUNT" -gt 50 ]; then
    echo "High read count"
elif [ "$COUNT" -gt 10 ]; then
    echo "Medium read count"
else
    echo "Low read count"
fi

# String comparisons
FILETYPE="fasta"
if [ "$FILETYPE" = "fasta" ]; then
    echo "Processing FASTA file"
fi

# File tests
if [ -f "data.txt" ]; then
    echo "File exists"
fi

if [ -d "results" ]; then
    echo "Directory exists"
else
    mkdir results
fi
Operator Meaning
-gt Greater than
-lt Less than
-eq Equal to
-ne Not equal to
-ge Greater than or equal
-le Less than or equal
-f Regular file exists
-d Directory exists
-s File exists and is not empty
= String equality
!= String inequality
-z String is empty
  • The spaces inside the brackets are required: [ "$A" = "$B" ], not ["$A"="$B"]. The [ is actually a command, and its arguments must be separated by spaces.
  • Use -gt, -lt, etc. for numbers and = / != for strings. Inside [ ], the > and < symbols mean redirection, not comparison.
  • Bash also offers [[ ... ]], a more forgiving version that supports pattern matching (e.g., [[ $FILE == *.fasta ]]).

Loops

  • For Loops
  • While Loops
  • Interpretation
#!/bin/bash

# For loop over a list
for BASE in A C G T; do
    echo "Processing base: $BASE"
done

# For loop over files
for FILE in *.fasta; do
    echo "Analyzing $FILE"
    grep -c "^>" "$FILE"
done

# For loop with a counter
for i in {1..10}; do
    echo "Iteration $i"
done
#!/bin/bash

# While loop with a counter
COUNT=1
while [ "$COUNT" -le 5 ]; do
    echo "Count: $COUNT"
    COUNT=$((COUNT + 1))
done

# Read a file line by line
while IFS= read -r LINE; do
    echo "Processing: $LINE"
done < input.txt
  • for loops iterate over a list of items (words, files, numbers)
  • while loops continue as long as a condition is true
  • Reading files line by line with while IFS= read -r LINE is very common. IFS= keeps leading and trailing spaces, and -r keeps backslashes literal.
  • Always quote "$FILE" to handle file names with spaces
  • If no files match *.fasta, the loop runs once with the literal text *.fasta. Guard with [ -e "$FILE" ] || continue if that matters.

Functions

  • Code
  • Interpretation
#!/bin/bash

# Define a function that OUTPUTS a value with echo
count_sequences() {
    local FILE=$1                       # local: visible only inside the function
    grep -c "^>" "$FILE"                # prints the count to standard output
}

# Function with multiple parameters
process_fasta() {
    local INPUT=$1
    local OUTPUT=$2

    echo "Processing $INPUT..."
    grep "^>" "$INPUT" > "$OUTPUT"

    # Capture the function's output with $( )
    local N
    N=$(count_sequences "$INPUT")
    echo "File $INPUT has $N sequences"
}

# Call the functions
N_PROTEINS=$(count_sequences "proteins.fasta")
echo "proteins.fasta has $N_PROTEINS sequences"

process_fasta "input.fasta" "headers.txt"
  • Arguments inside a function are $1, $2, … (just like a script’s arguments)
  • Use local for variables so they do not collide with names elsewhere in the script
  • To give back a value, echo it and capture it with $( ).
  • return N only sets the function’s exit status, an integer from 0 to 255 where 0 means success. It is not a way to return data: a count of 300 sequences would silently wrap around to 44. Use return only to signal success (0) or failure (non-zero).
  • Functions must be defined before they are called

Error Handling

  • Code
  • Best Practices
  • Interpretation
#!/bin/bash

# "Strict mode": put this near the top of every script
set -euo pipefail
#   -e           exit immediately if a command fails
#   -u           treat use of an undefined variable as an error
#   -o pipefail  a pipeline fails if ANY command in it fails

# Custom error checking
check_file() {
    if [ ! -f "$1" ]; then
        echo "Error: File $1 not found!" >&2
        exit 1
    fi
}
check_file "data.txt"

# Report the line number when something fails
trap 'echo "Error on line $LINENO" >&2' ERR

# Handle an expected "failure" explicitly
if ! grep -q "pattern" file.txt; then
    echo "Pattern not found"
fi
  1. Always include a shebang: #!/bin/bash
  2. Comment your code: explain what and why
  3. Use meaningful variable names: GENE_COUNT, not GC
  4. Check inputs: validate that files exist and arguments are correct
  5. Handle errors: use set -euo pipefail and explicit checks
  6. Make scripts portable: pass paths as arguments instead of hard-coding them
  7. Use version control: track changes with Git (see Appendix C)
  8. Test incrementally: build scripts step by step, running each piece
  9. Write a usage message: document how to call the script
  10. Log important steps: keep a record of what was done
  • grep returns exit status 1 when it finds no match. Under set -e, a bare grep that finds nothing will stop your script. Put it inside an if (as above) or add || true when “no match” is acceptable.
  • Error messages belong on standard error (>&2) so they do not get mixed into output files.
  • ShellCheck catches many common scripting mistakes. Paste in your script or install it locally, and editors such as VS Code and Positron can run it automatically through an extension.

Complete Script Example

  • Code
  • Usage
  • Interpretation
#!/bin/bash
# Script: fasta_stats.sh
# Purpose: Calculate basic statistics for a FASTA file
# Usage:   ./fasta_stats.sh sequences.fasta

set -euo pipefail

# Check arguments
if [ $# -ne 1 ]; then
    echo "Usage: $0 sequences.fasta" >&2
    exit 1
fi

INPUT=$1

# Check that the file exists
if [ ! -f "$INPUT" ]; then
    echo "Error: File $INPUT not found!" >&2
    exit 1
fi

echo "=== FASTA Statistics for $INPUT ==="

# Count sequences
SEQ_COUNT=$(grep -c "^>" "$INPUT" || true)
if [ "$SEQ_COUNT" -eq 0 ]; then
    echo "Error: no FASTA headers (lines starting with >) found" >&2
    exit 1
fi
echo "Number of sequences: $SEQ_COUNT"

# Total length (remove headers, newlines, and any Windows carriage returns)
TOTAL_LENGTH=$(grep -v "^>" "$INPUT" | tr -d '\n\r' | wc -c)
echo "Total length: $TOTAL_LENGTH bp"

# Average length (integer division)
AVG_LENGTH=$((TOTAL_LENGTH / SEQ_COUNT))
echo "Average length: $AVG_LENGTH bp"

# GC content (count upper- and lowercase G/C; awk gives a decimal percentage)
GC_COUNT=$(grep -v "^>" "$INPUT" | tr -cd 'GCgc' | wc -c)
GC_PERCENT=$(awk -v gc="$GC_COUNT" -v total="$TOTAL_LENGTH" \
    'BEGIN { printf "%.2f", 100 * gc / total }')
echo "GC content: ${GC_PERCENT}%"
# Make executable and run
chmod +x fasta_stats.sh
./fasta_stats.sh my_sequences.fasta

This script demonstrates several best practices:

  • Strict mode (set -euo pipefail)
  • Input validation (argument count, file existence, and a non-empty file so we never divide by zero)
  • Pipes for data processing
  • awk for a decimal percentage, since bash arithmetic is integer-only
  • Meaningful variable names and clear output
  • Comments explaining each section

Practice: Build Your Own Pipeline

TipHands-On Exercise

Build a complete analysis pipeline:

  1. Download a small bacterial genome and its protein or gene FASTA (~5 MB) from NCBI (see Appendix G for data repositories)
  2. Count the total number of genes (hint: count header lines)
  3. Calculate the genome size in base pairs
  4. Find the 10 most common 6-base sequences (hint: grep -oE "[ACGT]{6}", then sort | uniq -c | sort -rn | head; this counts non-overlapping 6-mers, which is fine for a first pass)
  5. Extract all genes with “ribosomal” in the header
  6. Save your pipeline as a shell script, with a usage message and set -euo pipefail, and commit it to a Git repository
